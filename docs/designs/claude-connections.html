Interaction and safety contract

  • Connection selection filters the model list; only choosing an offered model changes the chat. Never map an alias to another provider's model ID.
  • Subscription and API billing are distinct. Show identity only when Claude Code reports it; an unknown identity is never called Personal or Work automatically.
  • Multiple API keys remain separate provider records. Expose connection name before the key field. Never show keys in the switcher.
  • No automatic account rotation, quota pooling or paid fallback. No changes to a reply already running.
  • Desktop and shared web use the same control. At phone and folded widths, stack labels and identity text. Unfolded and split-screen layouts follow available width, not device names.
  • Native phone picker parity is follow-up scope, not claimed implemented by this renderer design.

Acceptance criteria and implementation status

Editable, self-contained design. Synthetic account data only. Controls illustrate the design, not real authentication or billing.
