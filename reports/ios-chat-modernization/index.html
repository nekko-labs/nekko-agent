Nekko iPhone redesign

Five screens of the native iPhone app brought closer to the desktop: borderless agent rows in the chat, a cleaner conversations list, computers you can open, providers set up from the phone, and a Nekko Cloud machine as a computer you pair with. Palette and type are the app's own (Theme.swift); the bubbles are unchanged.

What changed

  • Chips follow the desktop's one rule: 11 pt text, 4 pt corners, a 1 pt line, no fill; only the tone of the line changes (running, overdue, model).
  • Tool steps lose the card. One row: status mark, monospaced label, a chevron only when there is output. Output opens as a code well under the row, like the desktop.
  • Subagents become a group: a header with the fixed-box running dots and a count, child rows indented on a hairline, each with its model as a quiet chip (child's model, else the call's model_id, else the parent's).
  • Watch rows arrive on the phone for the first time: binoculars, what it watches and what wakes it, a then · line, and a live chip (countdown, overdue, triggered). The wake-up stops being a user bubble.
  • Approvals keep a card, because they are the one thing that needs you, but the stroke goes: a warm tint on the surface and a risk chip instead.
  • Title bar carries state: Working dot, computer, model. Send becomes Stop while a run goes, as today.

What the page is made of

  • Round trip is measured by the phone itself (the hello timing RouteProber already does for Check routes), sampled every 30 s while the page is open, so it works on any protocol version.
  • One new read channel, machine:summary, projects what the daemon already answers the desktop: machine:profile (chip, cores, RAM, GPUs, backends), engine:status (resident models, memory, startedAt for uptime), system:stats and gpu:stats (live load and temperatures), plus app:info. The phone view carries no paths, serial numbers or user names.
  • Models and Providers reuse models:list and providers:list. The toggle calls a new change-class providers:setEnabled (Face ID, like every change). Add a provider is §4.
  • Connection folds today's separate Connection screen in as a row that opens it, and shows this phone's Read / Change switches as the computer has set them.
  • Getting here: tap a computer in Computers, or the pill at the top of Chats. The action sheet goes; Connect / Rename / Forget move to the Edit menu and swipe actions.

Why this shape

Today providers:save is in PHONE_DENIED_FOREVER (decided 2026-10-19: provider keys never reach a phone). This flow keeps the spirit of that rule while granting the ask: the phone carries a key for a moment; it never holds one, never reads one back, and the computer never returns one.

  • Wire: a new change-class channel, providers:saveSealed, whose argument is the provider minus the key plus a ciphertext sealed to the computer's device public key (HPKE, P-256; the same shapes nekko-sync already uses). The relay and the phone's logs see only ciphertext twice over.
  • Gate: Face ID through the Secure Enclave change proof (IO-33), plus an optional Approve provider changes on the computer switch under Remote access, on by default for the first provider a phone ever adds.
  • Subscriptions (ChatGPT OAuth) stay out: that flow needs the computer's browser and keeps its token there. Claude plan sign-in is already removed by policy.
  • What the phone gets back: {ok, models: [...]} or the provider's error text. Never the key, never a base URL with credentials.

How it fits the engine you have

A cloud machine is the Docker image you already publish (nekkod + Local Web UI, NEKKO_SANDBOX=workspace-jail) started in relay-agent mode on a Fly Machine, so to the phone it is simply another computer: same pairing keys, same end-to-end encrypted frames, same allowlist. Nekko Cloud only mints the machine and hands the phone its pairing link.

  • No new chat protocol. session:create, streaming, approvals, watches, git and PRs all work as on a PC. The computer details page (§3) is the same screen.
  • Keys follow the sealed path of §4: the user's provider key is sealed to the machine's device key; Nekko Labs never holds it. Nekko-paid model credits are a later option.
  • Boundary change to record: the spec's Cloud never runs your tools on our servers becomes Cloud never runs tools on your computer; a cloud machine runs them in its own jail. Decision record needed.
  • Lifecycle: start on first chat (~8 s cold), stop after 15 min idle, delete after 7 days; the chat and its diff sync E2EE so nothing is lost when it sleeps.
