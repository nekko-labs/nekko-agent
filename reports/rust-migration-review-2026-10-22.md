# Rust migration (PF14) review, 2026-10-22

A review of the engine after the TS engine was deleted (2026-10-19), across five areas: leftovers from the migration, complexity, security, speed, and the Electron integration with performance against the old TS engine. Reviewed at `main` e91848ac. Each finding names its file and line at that commit.

Status key: **fixing** (a branch from this review), **decide** (needs a product call), **later** (recorded, not started).

## 4. Speed

| # | Finding | Status |
| --- | --- | --- |
| P1 | Every checkpoint deep-copies the transcript, re-reads and parses the chat from disk, clones it again, and the UI waits for the write. | fixing (`perf/nekkod-checkpoints`) |
| P2 | One store-wide write lock serializes every chat's saves. | fixing: per-chat locks |
| P3 | Launch parses every chat in full before `NEKKOD_READY`. | fixing: byte pre-filter for `activeRun` |

| P5 | Full chat parses on async threads to read one flag. | fixing: `SessionStore::meta` |
| P6 | Hub replay serializes under its lock; `remove(0)` trimming; frames copied per socket. | fixing |
| P7 | `usage:summary` re-reads both logs on every call; settings read from disk in `accounts.rs`. | later |
| P8 | No custom allocator; mimalloc is worth measuring on the JSON-heavy paths. | later |

Measured on the branch (M1 Max, release builds, three alternating rounds): launch with 500 chats (36 MB) 43 to 47 ms before, 23 ms after; frames per socket for a fast 400-token stream 412 before, about 46 after; one save of a 2.2 MB text chat 4.2 ms before, 2.1 ms after. Large-chat turn timings did not move measurably, and text gaps at 15 ms token spacing got about 0.5 ms longer. Full numbers are in `docs/perf-history.md`.

## 5. Electron integration, and Rust against the old TS engine

Desktop engine tests pass (24 of 24). Startup, the token handshake, restart with backoff (500 ms doubling to 5 s), rejecting in-flight calls on restart, and quitting all work. On quit nekkod exits 5 ms after stdin closes and stops its children.

| # | Severity | Finding | Status |
| --- | --- | --- | --- |
| E1 | high | SIGTERM or a crash of nekkod orphans its children on macOS (reproduced: an MCP server left with ppid 1). | fixing (`fix/engine-lifecycle`) |
| E2 | medium | A binary that fails to spawn leaves the engine stuck until the app restarts (Node emits no `exit`). | fixing |
| E3 | medium | A daemon that never prints its ready line is never restarted. | fixing |
| E4 | medium | Renderer calls have no deadline when nekkod is wedged. | fixing: heartbeat |
| E5 | low | The endpoint IPC handler gives the token to any sender. | fixing |
| E6 | low | Nothing locks the data dir; the CLI and the app could run two daemons on it. | fixing |
| E7 | low | nekkod inherits Electron's broad hardened-runtime entitlements (JIT, disabled library validation). | later (needs a signing pass) |

Benchmarks (`scripts/bench-chat-turn.mjs --fake --runs 10`, M1 Max, medians of two passes). Old is 6592eb5c, the last commit with the TS route; new is e91848ac.

| | old TS route | old daemon route | Rust only (now) |
| --- | --- | --- | --- |
| first text, idle | 4.7 / 5.7 ms | 3.6 / 4.0 ms | 3.4 / 3.7 ms |
| first text, 4 searches loading | 1,285 / 1,193 ms | 4.7 / 3.6 ms | 20.3 / 23.8 ms |
| approve to result, loaded | 507 / 467 ms | 2.6 / 2.4 ms | 7.9 / 11.0 ms |
| queue drain, loaded | 1,002 / 951 ms | 241 / 205 ms | 24.7 / 20.9 ms |
| workspace search, loaded | 172 / 162 ms | 312 / 169 ms | 93 / 92 ms |
| engine memory (RSS) | 23 MB + 129 to 190 MB Node | 25 MB + 107 to 113 MB Node | 26 to 29 MB |
| cold start to first call | about 212 ms (backend ready) | | 33 ms |

Idle, the engines are the same within noise. Under load the old TS route stalled for over a second. The "loaded" rows do not compare like for like: on the old commit the load ran in the TS host, and now it runs inside nekkod. The old daemon route also kept a chat busy for about 200 ms after each reply, which the bench had to retry around. Dropping the Node backend saves 100 to 190 MB of memory.
