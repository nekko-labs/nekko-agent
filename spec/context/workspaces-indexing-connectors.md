# Workspaces, indexing & connectors

- **Workspaces** `[shipped]`, multi-root folder add/remove/activate, chats bound to one primary workspace plus optional supporting workspaces so index + per-project memory engage across every selected folder while tools keep the primary as their working directory.
- **Indexer** `[shipped]`, workspace file tree, regex-based code outline, search; index-grounded context merged across a chat's selected primary and supporting folders.
- **Projects page** `[removed 2026-07-18]`, the dedicated Projects view (folder add/remove, index status, file browser) was retired to keep the rail focused. Folders are added from a chat's **+ → Folder** menu or the Context Inspector; files are browsed in the right panel's Folders accordions; the index keeps powering `@` file mentions and context under the hood.
- **Connectors** `[shipped]`, GitHub/Linear/Slack/Discord (token-based, real REST), Jira (site URL + email + API token) and Microsoft Teams (incoming webhook for posting, optional Graph token for reads) `[shipped]`, Gmail/Drive (paste an OAuth access token; one-click OAuth flow still pending Google client creds); connector snippets fed into context. **Official brand icons**: full-colour marks for multi-colour brands (GitLab, Slack, Jira, Teams' two-person mark, Gmail, Drive, Trello, Todoist, ClickUp, and Telegram on the messaging card); single-colour Simple Icons (CC0) for Discord and Asana; GitHub and Linear follow the theme ink so they stay visible in light mode `[updated 2026-10-17]`. **Layout** `[updated 2026-10-17]`: the Connectors tab fills the available width, with connector cards (and the Telegram messaging card) in a 1/2/3-column grid keyed to the view's own width (container queries, about 768px and 1152px); primary actions (Connect, Enable) sit at the card's right edge. Also **validate-on-connect**, Connect stores the token and immediately does a real fetch, surfacing a bad token as an inline error instead of silently "connecting"; each card links to where to get its token.
- **Nekko inside other agent tools** `[shipped]`, one-click install of the app as an MCP subagent into detected agent CLIs (Claude Code, Codex, Cursor, Windsurf): the app is already an MCP server (`nekko-agent mcp`), so connecting writes that server into the other tool's config (a backup is made first), and a copyable config snippet covers tools we can't write to. From then on Claude Code or Codex can hand Nekko scoped tasks, which run under this app's guardrails on this machine's models.
