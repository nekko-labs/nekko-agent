# Privacy Shield: control what a cloud model receives (2026-10-22)

`[v1 implemented; unit-tested (detectors, vault, streaming restore, wrapper, panel) and verified end to end against the real daemon with a scripted provider (the wire never carries the value; the tool and the saved chat keep it); panel verified in an isolated hidden renderer fixture, dark and light, with matched before/after captures; not yet checked in the packaged app, Local Web UI, narrow widths or macOS]`

**User intent:** use a cloud model without handing it personal data and secrets, see exactly what it would receive, and decide per value. Competitive with harnesses that ship a "privacy filter" between agent and model. Design: [`docs/superpowers/specs/2026-10-22-privacy-shield-design.md`](../../docs/superpowers/specs/2026-10-22-privacy-shield-design.md). Why placeholders at the model-client seam: [decision 0003](../../docs/decisions/0003-pseudonymize-private-values-at-the-model-client.md). User docs: [docs/privacy-shield.md](../../docs/privacy-shield.md).

- **Shield switch** in the composer's privacy row (Offline · **Shield** · Incognito), per chat, with an app-wide default (`settings.privacyMode`). **Off unless switched on**: chats behave exactly as before.
- **What it replaces**, before a request leaves the computer: email addresses, phone numbers (international, US, Japanese), card numbers (Luhn-checked), US SSNs, My Number (check digit), public IPv4 addresses (private, loopback and link-local are left alone), API keys, tokens, quoted or env-file passwords and URL passwords, the computer's account name in home-folder paths, and the user's own **terms** (clients, codenames, names; `settings.privacyTerms`), each as a typed placeholder such as `[PII_EMAIL_1]`. A value keeps its placeholder across every request of a reply, so prompt caching keeps working.
- **The agent still works:** what the model sends back (text, reasoning, tool call arguments, errors) has the real values put back before a tool runs or anything is saved or shown, including placeholders split across stream chunks. The transcript on disk keeps real values; Incognito still decides whether it is saved.
- **Preview and control** (the Shield panel): every value the shield would replace in the draft and the chat so far, what the model reads instead, and where it occurs; **Send** keeps one value as written in this chat (`session.privacy.allow`), **Hide again** undoes it; per-kind switches for this chat; the user's terms for every chat; "your message as the model reads it". The list is the engine's own redaction (`privacy:preview`), not a renderer copy.
- **Covered calls:** every agent turn request, sub-agents (they inherit the parent's `privacy`), chat titles, suggested replies and prompt-part fill, and compaction summaries.
- **Boundaries:** detection, the placeholder map and the preview run in the daemon on this computer; nothing new is sent anywhere. The placeholder map lives in memory for one reply and is never written. Logs record counts by kind, never values. `privacy:preview` is not on the phone allow-list. Local models on loopback get no shield (nothing leaves the computer); a "local" server on another machine does. Claude Agent chats are out of reach (Claude Code sends their requests) and the panel says so.
- **Not covered yet (planned):** names and addresses in prose unless they are terms (on-device NER), images, image-generation prompts, repository review and workspace one-shots, a "review before send" gate, a settings page for the default and terms, switching the shield from the phone apps, a per-reply "values hidden" badge, and a local-model "generic rewrite" pass.
- **Acceptance:** with the shield on and a cloud provider, the request body holds no detected value and holds its placeholder; a tool call that uses the placeholder writes the real value; the saved transcript holds real values; turning it off, a local provider, or an allowed value sends text as written.
