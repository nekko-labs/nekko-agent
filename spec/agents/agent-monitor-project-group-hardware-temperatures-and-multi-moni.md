# Agent Monitor Project group, hardware temperatures and multi-monitor Dynamic mode (2026-10-18)

User intent (Philip): (1) the Agent Monitor gets a **Project** group showing the connected project-management connector (Linear, Jira, Asana, ...), or, without one, the repo's own task file such as a tasks.md; (2) the Hardware monitor shows simple CPU, GPU and memory temperatures in their own rows where available; (3) Dynamic mode gains multi-monitor support: a multi-monitor button left of the Monitors toggle, a hover dropdown like the grid picker listing the screens in a row to toggle, a swipe-in-from-the-left / shrink-to-the-right animation, the main screen always on, a divider, and two view options ("prioritize empty windows" or "prioritize the main window"). Each screen's window has the same left nav and top-right toolbar and navigates on its own.

- **Project group** `[implemented; unit-tested; isolated renderer screenshots, light and dark]`: replaces the Agent Monitor's Tasks section and is always shown. Connected task connectors (Linear, Jira, Trello, Asana, Todoist, ClickUp, a picked Tasks file) come first, one tab per source, the single source named under the header. With none connected it reads the chat's own project folder (its worktree when it has one) for `TASKS.md`, `TODO.md`, `TODOS.md`, `BACKLOG.md` or `ROADMAP.md` (that preference order, any case), lists the open `- [ ]` items under their headings, and links the file name to the in-app viewer. With neither it offers Connectors and, when the chat has a folder, adding a TASKS.md. Clicking a task still only fills the composer. The checklist parser moved to `packages/shared` so the connector and the panel parse alike. Reads go through the existing file bridge; no new permission, channel or network call.
- **Temperatures** `[implemented; Rust and TS held to one golden set; live GPU reading verified on one Windows machine]`: each Hardware row shows its sensor at the right of its label (thermometer glyph, °C), warning colour from 80°C and danger from 90°C. GPU rows use each device's own reading, now asked of `nvidia-smi` in the same query (`temperature.gpu`; a driver that rejects the field is asked again without it). `system:stats` gains optional `temps { cpuC, memoryC, gpuC }`, the hottest plausible sensor per row: Linux hwmon (k10temp/coretemp/zenpower for CPU, spd5118/jc42 for DIMMs, amdgpu/nouveau/i915/xe for GPU), Apple Silicon sensors through IOKit (daemon only), and on Windows the ACPI thermal-zone performance counter read with PDH (no admin rights, no process). The board-level GPU sensor fills in only for a lone GPU without its own reading. Absent sensors show nothing rather than a guess; a monitor that is off shows no temperature. Memory temperature on Windows needs a kernel driver and is not offered; many Windows desktops publish no thermal zone, so CPU stays empty there (true of the verification machine). The TS fallback reads Linux hwmon only.
- **Multi-monitor** `[implemented; main-process policy unit-tested with a fake screen and clock; dropdown renderer-verified in an isolated fixture; real second-screen windows and the swipe animation not yet seen on hardware]`: in Dynamic, a two-screen button (`n/m` on) sits at the right end of the wall toolbar, after the layout segments and the snap magnet (it sat just left of the toolbar's Monitors button until that button moved into the Monitors panel). Hover, focus or click opens a dropdown in the grid picker's frame: every connected screen as a tile in reading order (left to right, then top to bottom), drawn to its shape; the main window's screen is marked Main and cannot be switched off; the window's own screen is marked Here. A divider, then **View options**: **Prioritize empty windows** (default: a new agent goes to a screen whose wall is empty, else the emptiest, the main screen winning ties) or **Prioritize the main window** (new agents stay on the main screen). Switching a screen on opens a full Nekko window filling that screen's work area that grows from a 64px strip on the left edge (280 ms ease-out); switching it off shrinks it into the right edge and closes it. Reduced motion skips the swipe. Each screen window has its own left nav, title-bar toolbar, wall and Agent-tab layout (per-screen browser storage keys); only the main window writes the shared wall setting. A screen window starts on its new-chat screen (see the 2026-10-27 entry below). A window keeps agents it creates itself; agents made from the main window's buttons follow the placement option; agents that appear from elsewhere (CLI, phone, automations) are placed after a 600 ms wait for their creator to claim them. The choice of screens and option persists in `display-windows.json` in the data dir and is restored at launch; a screen that is unplugged loses its window but keeps the preference, closing a screen window with its X switches that screen off, and hiding the main window to the tray hides the others. Screen windows never open the setup wizard. Desktop only: web and phone builds have no button.
- **A second window opens ready to chat (2026-10-27).** User intent (Philip): "when opening a new second window for nekko agent, have it be a blank with the new chat window ready. Keep focused mode if that's what they were using or dynamic mode but set to default two panes. Allow the two be in different modes. So one window is focused and the other is dynamic mode." The Screens button now shows in Focused as well as Dynamic. A screen or desktop window opened for the first time starts in the opener's mode: Focused on a fresh blank chat, or Dynamic with the grid at two panes side by side (2 x 1) and the blank chat in the first. The opener's mode is handed over in browser storage (`nekko.screenOpenerMode`), written just before the screen is switched on. An emptied screen wall opens a new chat again and keeps its mode (the main window still turns Focused when emptied). A screen window always makes its own blank chat rather than reusing one, since it cannot see which blank chat another window shows. Each window keeps its own mode, so one can be Focused while the other is Dynamic. An untouched blank chat does not count toward a wall's size for **Prioritize empty windows**, so a fresh screen still reads as empty. `[implemented; unit-tested; hidden fixture shows Focused and Dynamic second windows and the Focused toolbar's Screens button, before and after; real second-screen windows not seen on hardware]`
- **Screens dropdown stays open (fixed 2026-10-24).** User report: "the multi-monitor panel keeps closing on hovering or clicking." Two causes: the dropdown hangs from the title bar, whose drag region handed the pointer to the OS over the panel's non-button areas (so it closed on hover and swallowed clicks), and a click on the button toggled shut the panel that hovering had just opened. The panel and its hover bridge now opt out of the drag region, and clicking the button only opens it; Escape or a click outside closes it. `[implemented; source-pinned test; hidden Electron fixture shows the panel staying open after hover then click, which closed it on main; real title-bar drag behaviour on macOS not checked by hand]`
- **Desktops (macOS Spaces) on one screen (2026-10-24).** User intent (Philip): "for multi-monitor, let's add support to use spaces/desktops on a single monitor as well. Show if they have multiple currently open." Then, on how to get there: "switch me there now is ideal, but we should tell the user we need permissions for this... if they don't want to give it, we'll just have it open next time you switch screens. Give an abstract visual video of the screens switching in a monitor and then the new window opening up on it."
  - With two or more desktops on the main window's screen, the Screens dropdown shows a **Desktops** row (Mission Control's numbering, full-screen apps left out) drawn at that screen's shape: the main window's desktop is marked Main and always on, the current desktop has an accent dot, a waiting window's desktop is dashed and marked Waiting. On one screen the lone Screens tile is hidden and the toolbar button counts desktops (`2/3`). One desktop, or another OS: nothing changes.
  - The desktop list is read from macOS's `com.apple.spaces` preferences through `defaults` (no permission needed). The current desktop is asked of the window server (`CGSGetActiveSpace` through JXA, no permission needed), because the Dock rewrites that preference lazily: its current desktop can stay on an old desktop indefinitely, and a switched-on desktop's window then never appeared (fixed 2026-10-24, seen live: preference said desktop 1 while desktop 5 was active). The preference's value is the fallback if JXA fails. Both are read at launch, on every desktop switch (`NSWorkspaceActiveSpaceDidChangeNotification`, read again 400 ms later) and when the main window takes focus (which also records the main window's desktop).
  - macOS offers no public way to put a window on a chosen desktop; a window appears on the active desktop when shown. So turning a desktop on makes a full Nekko window (its own wall, keyed `space-<id>`) and holds it hidden until you are on that desktop. The first time, an explainer opens in the dropdown: a looping abstract monitor that slides to the next desktop and swipes a Nekko window open (static on reduced motion), why Accessibility is needed, that it also enables "Nekko, switch to desktop 2", and two choices. **Allow and switch** saves `switch` mode, asks macOS for Accessibility (its own dialog, once; the first switch also brings macOS's one-time "control System Events" Automation prompt, declared by the `apple-events` entitlement and `NSAppleEventsUsageDescription`) and, with it, jumps there by pressing Mission Control's shortcuts through System Events: Ctrl+number when "Switch to Desktop n" is on, else Ctrl+Right/Left steps (on by default). **Open when I get there** saves `arrive` mode: the window opens the next time you go to that desktop. Either can be changed later under View options; `switch` without the permission falls back to waiting and says so. The choice is saved in `display-windows.json` (`spacesMode`).
  - Desktop windows last for the session (not restored at launch), are left alone when screens are plugged or unplugged and when the main window goes to the tray, take part in new-agent placement once shown, and close with their X or by toggling the tile off. Only the main screen's desktops are listed when "Displays have separate Spaces" is on.
  - `[implemented; policy unit-tested with a fake Mission Control (hold until arrival, switch with Accessibility, main desktop follows focus, screens unaffected); prefs parser unit-tested and read live on a 3-desktop Mac; dropdown and explainer screenshotted and recorded in a hidden fixture, light and dark; keystroke switching and the Accessibility dialog not run (they would move the verifying machine's real desktop); packaged app not checked]`
