# Chat groups and tags: your own groups and tags for chats

`[implemented; unit-tested and server-rendered in component tests; drag and drop, the picker's keyboard use, the popovers and the header crumb not yet verified in the running app]`

## User intent

Put chats in groups of the user's own (for example "Frontend fixes", or just a colour) and tag them (#bug, #review). A chat still moves through the activity groups as it works (Building, Verifying, Watching, Done) and can still be archived, but wherever it ends up, chats of the same group stay together and say which group they belong to. The point is easier sorting in Done and in Archived.

## Behaviour

- **Data.** `Session.chatGroup?: string | null` holds the group's **id** (`g_` and ten lower-case letters or digits); unset or null means no group, one group per chat. `Session.tags?: string[]` holds the chat's tags, separate from the group and several per chat. A tag is trimmed, loses leading `#`s, has inner spaces turned into dashes, is capped at 32 characters, and is unique ignoring case within a chat (the first spelling stays). A group has an id, an optional name (trimmed, runs of spaces folded, at most 40 characters) and a required colour. A sub-agent chat has no card and does not take its parent's group.
- **Group identity and old chats.** The defined groups are a per-window preference, `nekko.chatGroups`, a list of `{ id, name?, color }`. A stored `chatGroup` is resolved in this order: a defined group with that id; else a defined group whose name matches ignoring case (a chat from before groups had ids stores a name); else a legacy name-only group shown as that name alone (the first spelling seen); an id no defined group has (made on another device) is an unnamed group. All of these cluster under one key, so a group and the chats that still store its name are one group. Assigning a chat to a group always stores the id (a legacy group gets an id and a defined entry first, keeping the colour it showed). Renaming moves the chats that stored the old name (or another id) to the id, and a rename to another group's name merges into that group. A rename to nothing leaves the group unnamed.
- **Migrating the preference.** The first read of an old `nekko.chatGroups` (the first version's list of names, or `{ name, color? }` entries) gives every entry a new id, keeps its name and colour, and saves the list back, so ids are made once. Entries with a bad colour lose only the colour; entries with neither a name nor a colour are dropped; names stay unique ignoring case. Chats are not rewritten: their stored names keep resolving to the migrated group by name until something assigns, renames or moves them.
- **Saving.** `session:setOptions` with `{ chatGroup }` (null clears it). It is on the Rust `OPTION_KEYS` allowlist and the running-turn `USER_FIELDS` list in `nekko-store`, and on the phone allowlist (`PHONE_SESSION_OPTION_KEYS` and its mirror `phone-access.json`), so it syncs; the phone apps show no group UI yet.
- **Making a group.** **New group** in the Agents panel's **+** menu (the same menu that creates agents, terminals and photos; not the board's) opens a small form: a name that is **optional**, and the colour swatches with **no colour selected** to begin with (nothing falls back to a default). **Create group** stays disabled until a colour is picked; Enter in the name field creates once there is one, Escape cancels. The same form is used for a group made from the picker's **Create group / tag…**. A group may have no name: it is shown as its colour dot alone. Its accessible name is "Untitled group (Teal)" for a preset colour and "Untitled group" for a custom hex; its sidebar cluster heading is the dot and the count. A group made with a name an existing group has reuses that group and takes the colour.
- **Empty buckets.** A defined group with no chats, active or archived, shows at the top of the Agents list as a quiet heading with its name and "Drag chats here". Once it has a chat it clusters as below.
- **Drag to assign.** Every cluster heading (with its chats) and every empty bucket is a drop target for chat rows dragged from the panel. Dropping one chat, or the whole selection when the dragged chat is part of it, sets `chatGroup` with the same save as the menu (a toast per failed chat, then the list refreshes); the target is highlighted while hovering and the chat flies to its place with the existing card motion. A drop on a group never counts as a project reorder or a board zone drop.
- **Managing a group.** Right-click a cluster heading or an empty bucket: **Edit group** (one small form in the menu: the name field, prefilled and optional, where an empty name leaves the group unnamed, and the colour picker with the current colour selected; **Save** applies both together in one write of the prefs, Enter in the name field saves, Escape or clicking outside cancels with no change) and **Delete** (leaves the defined list and clears `chatGroup` on its chats, archived ones included, which stay where they are; asks first through the delete confirmation only when the group has chats). All of these work by id.
- **Assigning.** The chat context menu (one chat or several selected) and the archived-row menu have **Groups and Tags**, which opens the picker below. With several chats selected a group is set on all of them, and a tag is on when every one has it: choosing it then removes it from all, otherwise it is added to those that lack it. Several chats are saved together; a failure shows a toast per chat and the list refreshes.
- **The group and tag picker.** One component for a group and tags, used by the sidebar menus and the new-chat composer. A search field is first (focus stays in it, arrows move the active option, Enter picks; no option is highlighted on open, the pointer highlights one only while over it, and typing a search highlights the first match; Escape closes or leaves the form; `combobox` and `listbox` roles, `aria-activedescendant`, `aria-multiselectable`). The very first option is **Create group / tag…**, which swaps the list for a small form: **Group** or **Tag**; a group has the optional name and the required colour above, a tag a name (leading `#` dropped); creating a group or tag also applies it to the chat(s) the picker is for, and creating a tag adds it to the saved list. Below come two labelled sections, **Groups** (a colour dot and the name; **No group** first when a chat has one) and **Tags** (#name), each A to Z ignoring case, unnamed groups after the named ones in palette order. The search matches every typed word against group names (and an unnamed group's "Untitled group (Teal)"), and tags, ignoring case and a leading #; a section with nothing left is hidden. Picking a group sets it, one at most, and picking the chat's own group again, or **No group**, clears it. Tags toggle. Picking a group, toggling a tag and creating all keep the picker open (creating returns to the list); clicking outside or Escape closes it. A check marks a tag every chosen chat has and a dash one only some have.
- **Known tags.** Every chat's tags plus a saved list in `localStorage` (`nekko.chatTags`), so a tag can exist before any chat uses it. A tag created in the picker stays in the list even when no chat uses it.
- **New chats.** A chat with no messages shows a compact button in the composer's bar, beside the model, that opens the picker; a group dot and a tag count show when set. While the chat has no messages the choice is only held in the renderer (`chatGroupHold.ts`, keyed by chat id): nothing is saved, so the chat gets no sidebar card or header breadcrumb and the new-chat screen is unchanged; the button and the picker's checks read the held choice. When the first message is sent (the chat's `messageCount` goes above 0) the held `chatGroup` and `tags` are saved through `session:setOptions`, once. A held choice is dropped if its chat is discarded first, and never reaches another chat. The sidebar's right-click picker on an existing chat still saves at once. A chat started from the **+** menu has the same button.
- **Header breadcrumb.** A chat window's title strip reads, from the Nekko icon on: `group / #tags / title`. A group part (the dot and the name; the dot alone when unnamed) and a tags part (`#a #b #c`, then "+N" for more) appear only when they have a value, each with its own separator; the title keeps its own element and is primary. The group and tags are labels, not buttons: hovering names them ("Group: BE", "Tags: #nc1 #test") and clicking does nothing; a chat's group and tags change from the sidebar menu or a new chat's button. Both parts truncate at narrow widths.
- **Tags on cards.** A chat card shows its tags as quiet metadata text (`#tag` in `--ink-faint` at the 11px floor with a 12px line, no pill, border or fill, 6px apart; at most three, then "+N") at the right end of the branch line, opposite the branch and its ahead/behind count (and before the PR chip when it rides that line); they truncate when the line runs out, and hovering "+N" names the hidden tags. A card with no branch line (no Git repository, or Git hidden in the view menu) shows them on a line of their own directly above its last line. The same place is used when the card has no PR. A title-only card (no other lines) shows them under the title row; with the metadata lines off, no chips show.
- **Showing.** Inside every panel group (each activity, date, project or computer group, the None list) and every archived list (a project's **Show archived**, the Archived fold), chats of one group sit under a quiet sub-heading: name and count, collapsible, the fold remembered per panel group and chat group while the panel is mounted. Ungrouped chats follow, with no sub-heading. A cluster sits where its best-sorted chat would be; inside it the view's sort applies. Show more counts the clustered order and the open chat stays in reach (its sub-heading opens when it is opened). With no grouped chats nothing changes.
- **Colour.** Each group has a colour: one of six presets, the board's zone tints (`--zone-tint-0` to `-5`: teal, amber, coral, blue, pink, lime; mid tones that hold in light and dark themes), or any custom colour. It is picked with the colour picker, which starts collapsed as one row of swatches below the name field (8px between them and the field): the six presets, then the custom colours used before (newest first, at most ten), then a rainbow tile named "Custom colour…". The presets and saved colours are radio buttons (Tab steps through every colour in turn, presets then saved colours, then the rainbow tile; arrow keys also move and pick, wrapping; Space or Enter picks the focused one; a saved colour shows a small × on hover or focus, or Delete/Backspace removes it, which leaves groups already using it alone). The rainbow tile (aria-expanded) opens the theme settings' colour wheel with a vertical brightness bar centred in the room to its right (a solid, thin handle), and the hex field (a complete `#rrggbb` is kept, anything else ignored) under it, with no preview dot (the swatch row already shows the pick); picking a preset or the tile again closes it, with a quiet fade and rise. The wheel holds its own hue, saturation and lightness while it is dragged, so taking the brightness to black or white and back returns to the same colour rather than a grey. A group that already has a custom colour opens the picker collapsed with that swatch selected. A custom colour joins the saved swatches (`nekko.chatGroupColors`, case-insensitive, skipping a preset's own colour) once it is chosen for a group: when **Create group** is pressed with it, or when **Save** is pressed in **Edit group** with it. Dragging the wheel or typing a hex never adds to the list. Neither form has a Cancel button: clicking outside or Escape leaves without creating or saving. The picker is used when creating a group (the **+** menu's **New group** and the context menu's **New group…**) and in **Edit group** in a group heading's or empty bucket's right-click menu, which reuses the new-group form with **Save** in place of **Create group** (on the hex row when the wheel is open). A group from before colours were required, or a chat-only legacy group, has a default chosen from the palette by its name (or its id), so it is stable; a new group always has a colour. The colours are saved with the defined groups (`nekko.chatGroups`: entries of `{ id, name?, color }` where `color` is a preset's palette index or a custom lower-case `#rrggbb`, the user's own value rather than a style token; a bad colour is dropped, and the first version's plain list of names still reads). Editing a group applies the colour picked, merging into another group by name takes that group's, deleting removes the entry. Picking a colour for a chat-only group defines it, so it stays as an empty bucket if its chats leave.
- **Border.** Each cluster (heading and chats) and each empty bucket has a 1px rounded border in its group's colour (mixed 55% with transparent). The user asked for this, so it is the one place the panel draws a border despite the design system's space-not-borders rule. The drop highlight is a heavier ring over it.
- **Dot.** A chat card or archived row that sits inside its group's box shows no dot: the box's coloured border already names the group. Where a grouped chat is not boxed (**Cluster by chat group** off, or active cards in project grouping with manual order) its card and archived row show a small dot in the group's colour before the title, in every status and with metadata off. The open chat's header, group headings, empty buckets and the pickers keep their dots. Its tooltip and accessible name are "Group: <name>", or "Untitled group (Teal)" for an unnamed group. The card has no description line (it shows model, git and agent lines), so the dot leads the title.
- **Done.** In the Done activity group (grouped by activity) cards leave out the done check and the title moves left. Other statuses keep their glyphs, and so does a done chat under project, date or other groupings.
- **No clustering while dragging order.** Grouped by project in manual order, where cards are dragged into position, active cards are not clustered (only labelled). Archived lists still cluster.
- **Order inside a cluster.** Chats keep the panel's sort (most recently active first by default); a cluster only gathers them, so tags and the group never change the order and a newer untagged chat sits above an older tagged one. "Active" is the time the card shows (its last reply, while it is idle or done), not the save time: filing a chat under a group or tag saves it and bumps `updatedAt`, which must not lift it above chats with newer replies (`activityAt` in `agentPanelView.ts`). A chat that is working or has no reply yet sorts by `updatedAt`.
- **View menu.** **Show > Cluster by chat group**, on by default, saved with the other view preferences (`clusterChatGroups`).

## Acceptance criteria

- Moving a chat to a group saves the group's id as `chatGroup`, and the chat appears under that sub-heading in whatever group it is in, including after it changes activity.
- Removing it, or the last chat leaving a group, removes the sub-heading.
- Switching the preference off removes the sub-headings and keeps the labels.
- Names differing only in case are one group.
- A group's cluster and empty bucket are bordered in its colour; its chats carry a dot in that colour everywhere; the colour survives renaming.
- Cards in the Done group show no check.
- A group made from the **+** menu appears as an empty bucket, can be picked in the Group and tags picker, and takes a chat dropped on it.
- Renaming or deleting a group changes every chat in it, archived ones too; renaming an id group touches no chat that already stores the id.
- A group can have no name, never has no colour, and **Create group** stays disabled until a colour is picked; the + menu starts with none selected.
- A chat that stores a name (from before ids) is in the defined group of that name, ignoring case; an old saved list reads, gets ids once, and keeps its names and colours.
- A chat's tags are trimmed, unique ignoring case and at most 32 characters; several are allowed; up to three show at the right end of the card's branch line and "+N" stands for the rest.
- The picker's first option is Create group / tag…, then Groups and Tags, each A to Z; picking a chosen group again clears it; tags toggle across a multi-selection.
- A new chat's composer and an existing chat's context menu open the same picker and save to the chat; the header breadcrumb only shows the group and tags.
- The header shows `group / #tags / title` with absent parts and their separators left out. A named group is its name in the group's colour, with no dot; an unnamed group is its dot alone.

## Privacy and security

A group's id and a chat's tags are chat metadata stored in the chat file and synced like the title; nothing is sent anywhere new. The group's name and colour stay in this window's preference, so another device that gets the id shows an unnamed group until it has defined one. It is a phone-settable option (not guarded): it changes no tool, mode or data-flow permission.

## Out of scope

Filtering by group or tag, and the phone apps showing groups and tags (defined groups and the saved tag list are kept per window and do not sync).

Follow-ups, not built: typing #hashtags in the composer to tag a chat, and "group by tag" or "group by colour" in the view menu.
