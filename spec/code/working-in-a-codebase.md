# Working in a codebase

The user wires one or more **folders** into a chat (multi-root), choosing one primary folder and any number of supporting folders in the Context Inspector's Folders section. The primary is also picked from a folder menu at the start of the composer's bottom strip (project folders, No folder, Add folder…); switching or clearing it keeps the old primary as supporting, and the composer's + menu Folder attaches the new folder to the chat. The workspace gets indexed (file tree + code outline + search), with index search and workspace memory spanning the selected folders while the agent's working directory remains the primary. They talk to the model in a unified **Chat** surface, messages render as speech bubbles, and reasoning appears above each answer: inline and live while the model is thinking, and for cloud providers (which send short summaries) it stays inline. For local models, which send their full raw chain of thought, it folds to a single "Thought for 3s" row (expandable to inspect the reasoning) as soon as answer text starts, and saved local chats load folded (see *Tool calls grouped by purpose*). A multi-step turn's working steps (reasoning, tool calls, and inter-tool narration) fold into a single collapsible **activity group** ("Worked on 6 steps · read_file, grep") so a long run reads as one expandable line instead of a wall of "Used `<tool>`" rows; only the final answer stays a bubble. Risky commands trigger an approval prompt. Each user prompt reveals a subtle on-hover action row (its timestamp, Copy, Edit & resend, and **Reset here**, which rewinds the chat to that message and re-runs it), replacing the old single Regenerate button. If a local model returns an empty response mid-loop, the reply retries once with a nudge and, failing that, surfaces a clear marker instead of stalling silently. If a model instead **degenerates into repeating itself**, the reply is cut off the moment the output collapses into a cycle, keeping everything it wrote before the loop and saying plainly what happened and what usually helps, rather than streaming the same sentence for minutes. A live subtext under the conversation tracks the in-flight reply (elapsed, tokens/sec, tokens generated) and keeps a last-reply summary when idle. **Tokens/sec is decode throughput**, output tokens over the time the model actually spent generating them, summed across the reply's steps: it deliberately excludes prompt processing, tool runs, and approval waits, so it matches the figure the local runtime reports rather than being dragged down by however long the turn happened to take (Ollama's own `eval_duration` is used where it's offered; other providers are timed from first token to the usage report). Single-digit rates keep a decimal, since 8.6 and 9.4 tok/s are different answers to "is this model fast enough". The UI says **reply** for a chat exchange and **iteration** for one cycle of a long-running run; "turn" is gone from the surface. Markdown renders on both sides of the conversation, so a dashed list typed into the composer comes back as real bullets rather than raw dashes. The composer accepts pasted images and has a **+** menu for a photo, file, or folder; attachments sit in a thumbnail strip inside the composer card, and right-clicking any chat image offers Copy or Save. Images are sent to vision-capable models as multimodal messages, with larger previews and a full-size photo viewer on click (see *Photos from the web in replies, and the photo viewer*). The lightbox closes when clicking anywhere outside the photo, including blank dialog space, and has a large, visible Close button as well as Escape dismissal. Invoking a `/skill` adds a compact usage chip while keeping the user's own input separate; the full skill instructions still go to the model. Above the composer, a two-row instrument strip separates **how this agent runs** (mode, tools, and the Offline / Incognito privacy switches on the right) from **which brain it uses** (model, effort; thinking is a passive streamed-reasoning indicator, with cloud thinking always on and local overrides under model Expert options). Automate sits at the top right of the composer with a warning-colored lightning icon, and the context readout counts the draft as you type it, in the strip and in the Context Inspector alike. Per-chat control modes (Ask / Guardrails / YOLO, plus Offline and Incognito) govern how much it confirms. Once a reply lands, the same model that wrote it suggests what the user probably wants to say next: a few short follow-ups appear as one-click chips above the composer (clicking one sends it outright), and the single likeliest next message appears as ghost text in the empty composer that **Right Arrow** types in. The suggestions ride a small sideband call that persists nothing, vanish the moment a new turn starts, and simply stay away on failure.
