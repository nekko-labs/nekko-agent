# Chat actions and persistent reply measurements

[Implemented; synthetic desktop payload checks and matched light/dark, wide/narrow visual evidence verified] Git checkout options sit below the explanatory notices and each starts with its worktree or branch icon. Chat transcript right-click menus provide Copy chat (the full Markdown transcript) and Export as Markdown; export is no longer a header button. Message Copy actions include a copy icon and To composer actions are removed. Completed persisted assistant replies show a checkmarked Done. subtext, excluding live, interrupted and tool-call messages. Reply measurements belong beneath the reply inside the scrolling chat transcript as subtle, faint text, not in the fixed actions footer or a separate bordered bar. They expose output tokens/s, total generated output tokens and elapsed time during a run and afterward; missing historical measurements are explicitly unavailable, never fabricated. This placement correction is implemented; matched light/dark, wide/narrow renderer verification is pending. It changes presentation only and adds no data collection or external requests. Model and effort controls have an explicit gap. Copy only writes to the clipboard on an explicit click, and export downloads locally. Acceptance requires clipboard/export interaction checks and matched wide/narrow light/dark desktop evidence. Historical measurement persistence remains unsupported by this renderer-only change.

## New chats take focus and image-only turns

`[Implemented 2026-10-18; unit-tested (store, wall, both Anthropic adapters); not yet checked by hand in the running app]`

- **A new chat is the one in focus.** Wherever a chat is started (Ctrl+N, the command palette, the tray, a deep link, dictation, onboarding, Continue as stacked PR, a new image session, or a window's split compass), the new chat becomes the selected one. With the developer Chat surface on, it opens in the Chat tab as before. With it off, the app goes to the Agents wall and selects the new chat's window there, keeping the current layout (it used to be auto-added behind the window you were on, or, when started from another page, left you on the wall with the old chat still selected).
- **An image sent without words never breaks a chat.** Anthropic rejects a request that contains an empty text block, and a saved turn is resent with every retry and every later turn, so one screenshot pasted with no text (or an empty reply) made the chat fail with `messages: text content blocks must be non-empty` forever after. Requests now leave out empty or whitespace-only text (the image still goes), and skip a turn that has nothing left. The saved transcript is unchanged, so a chat that already hit this works again on its next Retry. OpenAI-compatible requests also omit the empty text part of a picture sent without words.

## Retry and model-change context transparency (2026-10-07)

[Implemented; isolated renderer interactions and matched visual evidence verified] A pending ask_user question is a normal waiting state, not an interrupted reply. Persisted-interruption detection and the recovery banner are suppressed while that question is pending. Recovery exposes one non-destructive **Retry** action (formerly Continue); Start over is removed. Retry resumes against saved conversation/work and displays approximate input-context tokens from included Context Inspector items, or explicitly unavailable when no bundle exists. This is not a billable-token or cost guarantee: live changes, tool schemas, compaction, truncation, provider tokenization and caching can alter the request or charges.

Changing model or global effort in an existing chat opens an informational dialog after saving the selection. No request is sent merely by selecting, and a running reply is not restarted. Subsequent requests assemble context as ordinary follow-ups do; a different model may not reuse provider caches. The dialog suggests a new chat with only necessary information to reduce input context. Effort remains global. No context is transmitted by the notice itself; existing provider consent/routing boundaries remain unchanged. Acceptance: question waits have no recovery banner; one Retry preserves saved work; estimates are clearly approximate; model/effort changes explain next-request semantics and the new-chat alternative. Windows Electron verification covers matched light/dark wide/narrow captures, deterministic assembled-context estimates, saved-transcript retry payloads including no-progress failures, Escape/Tab behavior and focus return. The recovery notice wraps across rows at narrow widths instead of squeezing its explanation into a thin column. Native clipboard/export delivery and real provider billing are separate follow-ups.
