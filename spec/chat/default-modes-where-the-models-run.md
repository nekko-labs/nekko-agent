# Default modes: where the models run (2026-10-22)

`[implemented 2026-10-22; shared, Mode panel and store golden tests pass; the daemon's Cloud-only refusal test and visual evidence are on the PR; not yet run in the full desktop app]` **User intent:** the four starter modes should be the four ways Philip actually wants to run a chat: cloud models only, local and cloud fused, local only, and *risky business* (an isolated sandbox with no internet). **What ships:** `STARTER_MODES` (packages/shared/src/saved-modes.ts, mirrored in nekko-store's `STARTER_MODES` and checked by the create golden set) is now:

| Mode | Runs on | Approvals | Models | What it sets |
| --- | --- | --- | --- | --- |
| **Cloud only** | worktree | Guardrails | cloud | `cloudOnly: true`, internet on |
| **Fusion** | worktree | Guardrails | local + cloud | `autoModel: true`, `autoProviderSwitch: true`, `cloudOnly: false`, internet on |
| **Local only** | worktree | Guardrails | local | `offline: true`, `cloudOnly: false`, `toolApproach: 'code'` (code mode, added 2026-10-22; see *Code mode: a chat's tools as code*) |
| **Risky business** | Sandbox | Ask | any (local recommended) | `executionMode: 'sandbox'`, `offline: true` where the model allows it |

A saved mode gained an optional `models` field (`ModelScope`: `cloud`, `fusion` or `local`). Like effort, a mode saved without it matches any chat and changes nothing; unlike effort, a chat reads as having no scope when none of its settings pins one, so a plain chat matches none of the three model starters. `chatModelScope(session)` reads it back: `offline` is local, else `cloudOnly` is cloud, else Auto with provider switching is fusion. The Mode panel no longer repeats model-routing or effort controls (#1960); use the dedicated model and effort controls in the composer. Saved modes and their stored model/effort options remain compatible. Renderer regressions and hidden macOS Electron evidence cover the simplified panel; native phone UI is unchanged. The old starters (Everyday, Deep work, Private, Untrusted repo) are gone for users who never saved a mode; users who saved one already have the old starters copied into `savedModes` and keep them. A star on a removed starter no longer resolves, so new chats fall back to the last-used defaults, as for any deleted mode.

**Cloud only** is a new per-chat field, `Session.cloudOnly`, a user field like `offline` (`setSessionOptions`, kept across running turns, inherited by `spawn_agent` children, not copied by fork, as `offline` is not). `cloudProviderAllowed(provider)` (shared/models.ts, `cloud_provider_allowed` in nekko-turn) refuses a local kind wherever it listens and openai-compat on a loopback address. The daemon's admission refuses a cloud-only turn on such a provider with "This chat runs on cloud models only. Pick a cloud model, or turn Cloud only off in the Mode panel." without calling it, and `spawn_agent` refuses to start a child on one. In the renderer the model picker lists only cloud providers and Auto's cross-provider switch never moves a turn onto this machine. **Fusion** is not a new router: it is Auto plus *Follow capacity & cost* (see *Model auto-mode, with profiles*), which already treats local providers as free and never takes a weaker model. A true per-turn local/cloud router stays planned, but no longer occupies a placeholder row in Mode. **Local only** is the existing Offline mode. **Risky business** relies on the sandbox's existing boundary (`--network none`, scoped folders only, host tools, MCP, connectors and delegation denied, Ask forced). Two sandbox chats are told apart by neither approvals nor Offline, so a sandbox chat on a cloud model, which cannot go offline, still matches Risky business. With a cloud model the conversation with that provider is the one thing that leaves the machine; the docs say so.

## Delegation routing boundary (#2186)

Implemented in the Rust daemon; verified on Windows by two route-policy unit tests, the real-daemon `delegation_guard` regression (ten routing cases plus resume/privacy checks), and existing refusal, Cloud-only admission, child execution, and cancellation regressions. Delegation remains available in ordinary cloud chats, but a cloud parent cannot start or resume a local-model child unless the chat opted into the existing Nekko router (`autoModel: true`). Fusion enables that router plus `autoProviderSwitch`; provider switching alone is not router consent. No new routing flag is introduced. Explicit `cloudOnly: true` always wins, including over Fusion and router opt-in.

The same boundary applies to explicit targets and saved default delegation routes, before target model discovery or child creation. Provider classification uses the existing cloud/local provider rules, not an ID allowlist. Local-to-local and cloud-to-cloud delegation remain available, subject to existing offline, incognito, depth, and provider/model validation. A refusal does not fall back to another route.

New and resumed children use the current saved parent's permissions rather than stale turn snapshots. Children inherit the existing router flags so nested delegation keeps the authorized routing scope; missing flags do not acquire permission from global chat defaults. Resuming rechecks the saved child's actual target against current parent permission before admitting its turn, and never clears an existing child Cloud-only boundary. Offline and incognito parents cannot resume children. Desktop UI and live provider behavior are outside this Rust-only verification scope.

**Boundary:** applying a mode never switches the chat's model. A cloud-model chat put in Local only keeps its internet, and a local-model chat put in Cloud only is not marked cloud-only; in both cases the panel shows a notice naming the model to pick. A new chat started in a starred mode has no model yet, so it takes the mode whole (the engine then refuses a mismatched first turn with its normal message). **Not yet:** switching the chat to a fitting model when a mode is applied, phone support (`cloudOnly` is not in the phone allowlist), and the automation daemon's own session creation (unchanged: it never applies the default mode).
