# Chat artifact cards and session-local documents

Implemented, focused-unit-tested; parent-owned desktop visual/interaction verification pending: the Agent Monitor's Artifacts disclosure starts collapsed, but a newly discovered distinct local artifact path expands that section and shows a static accent border/background with visible **New artifact** text and a polite accessibility status for ten seconds. Another new path restarts the full ten-second deadline, even if the total artifact count stays the same. Duplicate links, case-only path changes, metadata updates and previously seen paths reappearing do not retrigger. Initial history, switching sessions, missing or mismatched session data, and history arriving after null hydration establish a silent baseline. Manual collapse is respected until the next new distinct path; highlight expiry never collapses the disclosure. Session changes and unmount cancel pending timers. Discovery reuses the existing PlanRail assistant-message artifact list and never opens the whole Agent Monitor or adds file reads, permissions or network calls. Fake-timer tests cover path replacement, duplicates, hydration, session switching, deadline reset and cleanup; section markup/wiring tests cover collapsed defaults and accessible status. Native mobile is unchanged.

Implemented candidate, visual review pending: assistant replies expose explicit local document links as cards below the response. Cards use descriptive link labels (or a folder-based title for generic README/index names), retain the filename as secondary text, and require user activation to read files (images and HTML rendering cards, below, are the exceptions). The top of This prompt contains an Artifacts disclosure, closed by default, always showing a count including 0, with unique local documents from assistant messages in that session. Links in code samples, remote resources and executables do not become artifact cards. Local image markdown and explicit image links (SVG, PNG, JPEG, GIF and WebP) are artifacts, including in the session disclosure and global index. Image cards automatically load local files outside Sandbox, fill the available width up to 768 px and contain images within 640 px height, with title, filename and an Open source action scoped to the originating chat. Markdown image previews suppress the same image's additional response card; repeated image markdown itself is not deduplicated. SVG is rendered only as an inert img data URL, never mounted markup, so scripts and external SVG subresources cannot execute or fetch. Remote URLs, UNC shares, device paths and unsafe schemes are not auto-loaded; Sandbox does not read host files. This image-card update is implemented and focused-unit-tested; desktop visual/interaction verification is pending with the parent task, and native mobile is unchanged. Opening a document from a chat reuses or creates its file pane in that originating chat workspace, never globally focuses another chat’s copy. Sandbox host-file access remains disabled. Existing filenames are not silently renamed; titles improve discoverability without breaking links. Desktop renderer behavior is tested; native mobile surface is unchanged and visual inspection remains unverified. Cards are tinted from the theme accent `[implemented; contrast-tested; renderer-verified in an isolated fixture]`: a faint accent wash fading left to right, an accent-tinted border, extension chip and open arrow, stronger on hover. Like the merged-PR banner they follow the theme, preset and custom accent, but deliberately quieter (about 8% wash, 12% on hover) so a list of files never reads as a milestone. Title and filename hold WCAG AA on the wash in every shipped theme and preset.

## Rendering cards, `file://` links and live previews (issue #1095)

Status: implemented on desktop and unit/renderer-tested; captured in the hidden isolated Electron fixture (light and dark) but not yet reviewed in the running app; native mobile and the Local Web UI chat are unchanged.

**Intent.** When an agent builds a page or starts a preview server, the reply should show what was made, not just a filename: a picture of an HTML prototype, and a clear card for the dev server, without the app fetching anything from the network.

**HTML rendering card.** A reply link to a local `.html`/`.htm` file renders as a card with a thumbnail above the title and filename.
- The page is read through the same host read as the file pane (`readFile`), only once the card is within about 200 px of the viewport (IntersectionObserver); a card in a closed Agent Monitor disclosure is not read.
- It is drawn in an `<iframe sandbox="">` with `isolatedDocument` (CSP `default-src 'none'`, no connect, no forms): no script runs, nothing loads from the network, the frame has no app bridge, ignores the pointer and is out of the tab order. Laid out at 1280 × 800 and CSS-scaled to the card width, 200 px tall (the top of the page).
- Pages that are binary, truncated by the read cap or over 1,000,000 characters, and unreadable pages, keep the plain card with a short note instead of a thumbnail.
- Actions: **Open** (and a click on the thumbnail) opens the file pane in the originating chat, which keeps its preview/source switch and **Open interactive preview**; **Interactive** opens the same isolated interactive preview window (`nekkoPreview.open`) with the page source, shown only when the desktop bridge exists and enabled once the page is loaded.
- Sandbox: no host read at all; the card shows "Host file previews are unavailable in Sandbox" with both actions disabled.
- Accent-tinted like the other artifact cards; actions are real buttons with a focus ring; title and filename use `--ink`/`--ink-soft` for WCAG AA; no motion beyond the shared hover transition, which is removed under reduced motion.

**`file://` links.** `file:///C:/x.md`, `file:///home/me/x.md` and `file://localhost/...` are local artifacts (percent-decoded; the drive path loses its leading slash) for cards, the Agent Monitor list and the global Artifacts index, and open in the file pane from the reply's Markdown. `file://host/share` network paths, control characters and malformed escapes are rejected. A `file://` image becomes an image card, since Markdown does not draw it inline. The same file reached as a path and as a `file://` URL is one artifact.

**Live preview card.** An assistant link (or bare URL outside code) to `http(s)://localhost`, `127.0.0.1`, `[::1]` or `0.0.0.0` with any port and path becomes a **Live preview** card: the link label as title ("Live preview" for a bare URL), host:port and path, and **Open in browser**. It is an ordinary web link, so the existing window-open handler hands it to the user's browser (`shell.openExternal`); `0.0.0.0` is opened as `localhost`. URLs with credentials, other hosts and non-http schemes are not live previews.
- Privacy: the app never fetches a live preview (the renderer CSP would block it, and we do not auto-load network content), so there is no thumbnail. Live previews stay available in Sandbox, like any web link.
- They are listed in the reply and in Agent Monitor's Artifacts disclosure (counted once per URL), but not in the global Artifacts index, which lists files.

**Acceptance.** Links inside code spans and fenced blocks never produce cards. A reply with an HTML link, a localhost link and an image shows a rendering card, a live preview card and an image preview, each once. Verified by `chatArtifacts.test.ts` (file URLs, loopback detection, bare URLs, code exclusion, dedupe) and `ChatArtifacts.test.tsx` (lazy read, sandboxed scriptless frame, scaling, actions, size cap, Sandbox, live card, index exclusion); visual evidence from `apps/desktop/scripts/chat-artifacts-evidence-sandbox.cjs`, where the fixture page's inline script is reported as blocked by the frame sandbox.
