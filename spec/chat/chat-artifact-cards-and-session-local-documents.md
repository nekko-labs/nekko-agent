# Chat artifact cards and session-local documents

Implemented, focused-unit-tested; parent-owned desktop visual/interaction verification pending: the Agent Monitor's Artifacts disclosure starts collapsed, but a newly discovered distinct local artifact path expands that section and shows a static accent border/background with visible **New artifact** text and a polite accessibility status for ten seconds. Another new path restarts the full ten-second deadline, even if the total artifact count stays the same. Duplicate links, case-only path changes, metadata updates and previously seen paths reappearing do not retrigger. Initial history, switching sessions, missing or mismatched session data, and history arriving after null hydration establish a silent baseline. Manual collapse is respected until the next new distinct path; highlight expiry never collapses the disclosure. Session changes and unmount cancel pending timers. Discovery reuses the existing PlanRail assistant-message artifact list and never opens the whole Agent Monitor or adds file reads, permissions or network calls. Fake-timer tests cover path replacement, duplicates, hydration, session switching, deadline reset and cleanup; section markup/wiring tests cover collapsed defaults and accessible status. Native mobile is unchanged.

Implemented candidate, visual review pending: assistant replies expose explicit local document links as cards below the response. Cards use descriptive link labels (or a folder-based title for generic README/index names), retain the filename as secondary text, and require user activation to read files. The top of This prompt contains an Artifacts disclosure, closed by default, always showing a count including 0, with unique local documents from assistant messages in that session. Links in code samples, remote resources and executables do not become artifact cards. Local image markdown and explicit image links (SVG, PNG, JPEG, GIF and WebP) are artifacts, including in the session disclosure and global index. Image cards automatically load local files outside Sandbox, fill the available width up to 768 px and contain images within 640 px height, with title, filename and an Open source action scoped to the originating chat. Markdown image previews suppress the same image's additional response card; repeated image markdown itself is not deduplicated. SVG is rendered only as an inert img data URL, never mounted markup, so scripts and external SVG subresources cannot execute or fetch. Remote URLs, UNC shares, device paths and unsafe schemes are not auto-loaded; Sandbox does not read host files. This image-card update is implemented and focused-unit-tested; desktop visual/interaction verification is pending with the parent task, and native mobile is unchanged. Opening a document from a chat reuses or creates its file pane in that originating chat workspace, never globally focuses another chat’s copy. Sandbox host-file access remains disabled. Existing filenames are not silently renamed; titles improve discoverability without breaking links. Desktop renderer behavior is tested; native mobile surface is unchanged and visual inspection remains unverified. Cards are tinted from the theme accent `[implemented; contrast-tested; renderer-verified in an isolated fixture]`: a faint accent wash fading left to right, an accent-tinted border, extension chip and open arrow, stronger on hover. Like the merged-PR banner they follow the theme, preset and custom accent, but deliberately quieter (about 8% wash, 12% on hover) so a list of files never reads as a milestone. Title and filename hold WCAG AA on the wash in every shipped theme and preset.
