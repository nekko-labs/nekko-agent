# End-to-end encrypted sync for Pro and Team (2026-10-22)

`[implemented 2026-10-22 and tested end to end against the local Nekko Cloud stack; not live: the Supabase project isn't connected, Nekko Cloud isn't deployed with it, no outside cryptography review yet; the iPhone screens build only on macOS CI]` Design and threat model: [docs/SYNC-ENCRYPTION.md](../../docs/SYNC-ENCRYPTION.md). Decisions: [0004](../../docs/decisions/0004-supabase-for-identity-only.md), [0005](../../docs/decisions/0005-recovery-key-as-a-p256-key-and-sealed-account-record.md), [0006](../../docs/decisions/0006-lockout-recovery-without-a-vendor-key.md).

**User intent, round 2 (2026-10-22):** Philip asked to build the rest: Nekko Cloud sign-in with "our Supabase auth", a custom login screen in the existing design language, "a nice animated visual for the syncing", the sync engine and Settings → Sync on the computer, the iPhone's sync screens, the offline research key and an outside cryptography review; and to find out what other companies do for people who get locked out ("are they storing a backup key for the users?").

**User intent:** Philip asked (2026-10-22) for end-to-end encryption, "extremely secure", for storing and syncing messages on the server, as a Pro-and-up feature: Nekko Labs must not be able to see users' messages unless they explicitly allow us to use them to improve the app anonymously, and even then the data stays encrypted.

**Decisions:**
- **Zero-knowledge by construction.** Chats are sealed on the user's devices; Nekko Cloud stores only ciphertext, Padmé-padded sizes, keyed-hash object ids, revisions and device public keys. Keys: a 64-byte keyring per key epoch (record key ‖ id key) wrapped to each device's P-256 key (Secure Enclave on iPhone) and to a 256-bit recovery key; one AES-256-GCM key per record revision via HKDF from a fresh salt; account, epoch, collection, object id and revision bound as associated data (no relabelling or rollback).
- **No password recovery.** The only recovery is the recovery key shown once (55 Crockford base32 characters with a checksum). A password-derived key could be brute-forced by the server, which holds the wrapped keyring. Losing every device and the recovery key loses the synced copy, by design.
- **Revocation rotates.** Revoking a device kills its tokens and wraps; the remaining devices start a new key epoch, and Cloud accepts writes only under the newest one.
- **Pro and Team only for writes; never locked out of your own data.** Free keeps everything local. After a downgrade, pull, decrypt and *Delete everything synced* keep working; only uploads stop. Storage: Pro 5 GB, Team 20 GB per account (encrypted bytes).
- **Help improve Nekko Agent stays encrypted.** Off by default; turning it off changes no feature. The user picks what to share, the device redacts it, and seals it to Nekko Labs' research key, whose private half is offline only. Uploads carry no account, device or IP (unauthenticated route, request logging off, day-granular date), can be withdrawn with a delete token the device keeps, and expire after 180 days. Opting in never gives Nekko Labs the sync keys.
- **Adding a device needs the recovery key or an existing device.** By approval, the new device shows a 16-character fingerprint of its key and a syncing device approves it only after the user compares it on both screens, so a server-registered key can't be trusted silently.
- **Sign-in: Supabase Auth for identity only** (decision 0004). Email 6-digit code, or Apple, GitHub and Google in the browser with PKCE (loopback redirect on the computer, `nekko-agent://cloud-callback` on the iPhone). The Supabase access token is traded once for a per-device `nk_` token (180 days from last use) and dropped; the account, plan and all data stay in Nekko Cloud's Postgres. A beta signup's user is linked by email on first sign-in.
- **The recovery key is a P-256 key pair; the account record is sealed** (decision 0005). Each key epoch is sealed to the recovery key's public half, so devices never hold the recovery secret and rotations stay recoverable. A sealed account record lists the trusted devices and pins the recovery public key; rotation wraps only to devices in it.
- **What syncs:** every chat except incognito chats (never) and Local only chats (only when the user includes them in Settings → Sync). Pictures and attached files are left out of the synced copy; a chat whose text is over 1 MB is skipped and counted. Newest `updatedAt` wins; a chat a turn is running in is never overwritten. Deletions sync as sealed tombstones. The iPhone reads synced chats (offline too) and approves devices; it doesn't change chats.
- **Where keys live:** macOS Keychain, Windows Credential Manager, a 0600 file on Linux, and on the iPhone a Secure Enclave key-agreement key (no Face ID per use: sync runs in the background and the app lock covers reading) plus the Keychain, this device only. A phone paired to a computer can never call the computer's `cloud:` or `sync:` channels.
- **Lockout** (decision 0006): no key Nekko Labs can use alone, ever. Today: the recovery key with a confirm-by-retyping step and a printable recovery kit (QR code), plus a prompt to add a second device. Proposed next, not decided: a recovery contact (split with the server), a Team admin recovery key (opt-in per member), and later optional PIN recovery in an enclave. Research: [reports/e2ee-lockout-recovery-2026-10-22.md](../../reports/e2ee-lockout-recovery-2026-10-22.md).

**Screens:** Settings → Sync on the computer (signed out, not on the plan, off, add this computer, waiting for approval, syncing, up to date, needs attention), a full-screen sign-in in the clean-start glass-and-prism style, the recovery key dialog (show once, copy, save kit, confirm), devices with fingerprints, Approve and Remove, and an animated picture (this device, the encrypted vault, other devices; sealed packets travel only while a sync runs, still otherwise and under reduced motion). On the iPhone: Settings → Nekko Cloud sync (also from the welcome screen before any pairing), the same states, a Canvas version of the picture, and read-only synced chats.

**Acceptance criteria:** a database copy reveals no chat text, titles or the chat a record belongs to; a modified, relabelled, rolled-back or cross-account record fails to open; a revoked device can't read writes made after rotation; Rust and Swift produce identical bytes for the shared vectors; Free-plan writes answer 402 while reads and deletion work; donations are stored with no sender information and open only with the research key.

**Implemented 2026-10-22 (round 2):** `apps/nekko-agent-api` sign-in (`/v1/auth/*`, Supabase JWT via JWKS or the legacy secret, migration `0003`, 9 tests) and `npm run dev:local` (PGlite and a fake Supabase Auth); `crates/nekko-cloud` (the engine, wired into nekkod as `cloud:*` / `sync:*`; unit tests and a three-device live test against the dev stack: sign-in, turn on, restore, approval, edits both ways, revoke and rotate, deletes, no plaintext on the server); the desktop's `components/cloud/` (Settings → Sync, sign-in, recovery dialog and kit, `SyncVisual`), with evidence captured through `apps/desktop/scripts/sync-evidence.cjs` (the real engine via the `bridge` example, hidden Chromium); the iPhone's `NekkoKit/CloudSync` (tests on an in-memory server) and `CloudViews`, `CloudDeviceKey`, and a UI test with screenshots (macOS CI); `scripts/research-key.mjs` and [docs/research-key-ceremony.md](../../docs/research-key-ceremony.md); the outside-review packet [reports/crypto-review-scope-2026-10-22.md](../../reports/crypto-review-scope-2026-10-22.md). **Not yet:** the Supabase project and deploy, Stripe plans, the research key itself and donation sharing, Android, the outside review, and iPhone screenshots from a device.

**Implemented 2026-10-22 (round 1):** `crates/nekko-sync` (reference implementation, 13 tests incl. bit-flip, relabel, rollback, rotation, wrong-device and recovery-typo cases; vectors cross-checked against Node `crypto`); `apps/nekko-agent-api` migration `0002_e2ee_sync.sql`, bearer tokens (SHA-256 only), `/v1/sync/*` and `/v1/donations` (15 tests on PGlite); `NekkoProtocol/SyncCrypto.swift` with `SyncCryptoTests` on the shared vectors (runs on macOS CI, not run locally).
