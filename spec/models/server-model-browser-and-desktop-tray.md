# Server, model browser and desktop tray

Requested 2026-10-01. The Model server and Agent server cards share a row above the model library on wide screens and stack on narrow screens. The model server uses the same power icon as existing runtime controls. Server settings save automatically after two seconds without edits or when a field loses focus; invalid values and failed saves remain visible without discarding the draft.

The model library is a two-pane browser: searchable model-family rows on the left, selected model details on the right. Downloaded families and individual variants show checkmarks. Quantizations, conversion publishers, formats and local folder providers for the same identifiable model share a family row, with their separate load, download and setup options under Variants. Different parameter sizes and trained models remain distinguishable. GPU guidance says "Fits on GPU", "Fits on GPU, but limited context size", or "Too big" when evidence supports it; CPU-only and unknown hardware are named honestly, and catalog estimates are not presented as measured context limits.

The sidebar plus menu closes after the pointer leaves the button or list, with a 220 ms grace period to cross the gap; re-entering cancels dismissal. The top-level sidebar workspace plus creates a new workspace with a terminal rather than inserting one into the active workspace. Repository-row controls are distinct: their plus creates an agent chat, and their terminal icon creates a shell, both in the clicked repository. The workspace list also shows saved chats whose windows are closed, grouped under their project, so reopening an older conversation does not require remembering its title in another view. Completed chats stay out of this list. Completing a session uses an X control (see *Chat completion X icons*) and moves it to the Completed list, where it stays read-only and restorable for 60 days before deletion. Completing a chat from its card, its saved-chat row or the row menu plays an exit on the row: it folds shut toward its left edge, a little stardust drifts out of where it vanished, then the space closes and the rows below slide up. The chat is saved as completed only after the row has gone; if saving fails the row comes back. The exit takes about 600 ms, the stardust fades within 900 ms, and both are skipped when reduced motion is preferred. The stored archivedAt field remains compatible with existing sessions. Chat headers put folder and branch details directly after the title, followed by a subtle slash divider before actions.

Desktop keeps a Nekko Agent tray icon. Its first action opens a new chat, followed by opening the UI, stopping/starting or restarting the Nekko service, and starting/stopping the model server. Closing the desktop window hides it to the tray while the service and running work remain alive. Explicit Quit shuts down the service and managed processes; the tray's Stop Nekko service stops the service without quitting the UI. Stopping the service is distinct from hiding the window, and restarting restores the UI connection rather than leaving a stale endpoint. Close-to-tray is existing behavior, not newly implemented by the 2026-10-13 notification batch. Keeping the UI hidden does not promise continued execution during OS sleep, shutdown or logout.

**Close guidance and playful farewell (2026-10-15).** `[implemented, focused tests and isolated Electron lifecycle checks; native desktop capture and real Windows notification click verification pending]` The first user close with a running service highlights Nekko's system-tray presence with a Windows balloon and a local companion explaining that agents remain running. The companion is a compact card with no scrollbar: an **X** in its top-right corner, and two slim buttons, **Got it** and **Shut down on close instead** (saves the preference and quits immediately). It dismisses itself after 15 seconds if left alone (2026-10-15; it used to stay until acknowledged and also offered Settings, which lives in the app). **Settings > Desktop behavior** selects keep-running-in-tray (default) or shut-down-on-close; explicit Quit and external installer/migration close requests still quit. **Settings > Fun** groups the existing mascot toggle with a separate default-on **Tray farewell** toggle. Subsequent hides show the smiling, blinking pixel Nekko with a varied goodbye for two seconds, without taking focus; reduced-motion disables blinking. Disabling farewell suppresses that decoration, not the first-close explanation. The companion anchors to the reported tray bounds, clamped to that monitor's work area, falling back to the work-area corner when no tray bounds are available; Windows controls overflow-tray visibility, so exact placement above a hidden icon is not guaranteed. The explanation is deferred while the service is stopped. Notification clicks explicitly restore/focus the main UI, never an auxiliary browser/preview/companion window, and open/focus the corresponding existing agent workspace pane (or open that chat if its pane was closed).
