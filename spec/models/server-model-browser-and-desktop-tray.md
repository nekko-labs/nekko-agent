# Server, model browser and desktop tray

Requested 2026-10-01. The Model server and Agent server cards share a row above the model library on wide screens and stack on narrow screens. The model server uses the same power icon as existing runtime controls. Server settings save automatically after two seconds without edits or when a field loses focus; invalid values and failed saves remain visible without discarding the draft.

Updated 2026-11-07 (the Agent server half superseded 2026-11-20, below: it moved to Settings > Server). The two servers are open sections, not cards, and their matching rows line up side by side: the header (name, power switch, launch switch), the description, and the status line (Running or Stopped, with the address to copy) each start at the same height, even when one description wraps to two lines. Each server's power control is a switch labeled with its state (Serving, Stopped, Working…, or why it cannot start, such as Not installed), the same kind of switch as "Start Server on Nekko Launch" beside it, because the old pill button read as a status badge. The image generation and MLX runtimes fold under a **Runtimes** disclosure below the model server's status, closed by default, like **Agent server settings**: most people never need to see which runtime build is installed.

**Models page rework (2026-11-20).** `[implemented; unit-tested and verified in hidden, network-blocked renderer fixtures (Find new models, the per-quant table, a failed load, Settings > Server); not yet checked in the packaged app]` Requested together with a design (`nekko-designs/models-page-design.html`).

- **The Agent server moved to Settings > Server.** It is how other programs reach this app, not part of the models it runs, so it left the Models page. **Server** is the last row of the rail's top block, after Connectors, and its section leads the Settings page. The header is the whole answer most people need: the name, one line on what it is for, the status word with its dot (Running, Stopped, Working…) and the on/off switch at the top right, then the address to copy and the request count while it runs. Everything else (Start with Nekko, where it is reachable from, the port, the address clients use, the token, the environment lines, the CLI and the MCP clients) waits behind one **Configure** row with a gear icon and a chevron that turns as it opens. The CLI and MCP parts are groups in that fold, not tabs. The Model server stays on the Models page and no longer shares a row.
- **Running now leads the local section.** The models in memory (and loads on their way) are plain rows under a **Running now** label directly below the Model server, above the library, each with its quant, the memory it holds, its context against the model's own maximum, where it runs (all on the GPU, or partly on the CPU in the warning colour), how long until it unloads, and Settings, Keep loaded and Unload. One meter shows how much of the machine's model memory they hold together. It used to be a box beside the variant list.
- **Two halves, one switch.** Under **Models** a two-way slider picks **On this machine** (with the count) or **Find new models**; Downloads and Folders sit at the right of that row as quiet tabs, and the slider's thumb rests on neither while one is open. A machine with no models opens on Find new models; one with models, on On this machine. On this machine filters the library only (never a web search) and lists families on disk; System models and Decision models live here. Find new models searches Hugging Face, and before a search it leads with **Best for this machine** (see [Hardware-aware model recommendations](hardware-aware-model-recommendations.md)); models already on disk still appear there with a check. An upgrade nudge shows on both halves.
- **Each row says what matters.** A family row is two lines: its name, then its parameters, its size (or "3 variants, 3.9 GB to 9.6 GB") and whether it fits on the GPU ("in memory" when loaded). In Find new models the second line is the parameters, how many quants with their size range, and whether the smallest fits (estimated). The selected family's heading line gives its parameters and what is on disk, and below its variants an **On <GPU>** group shows the weights, what each 1k tokens of context costs, the context that fits beside what is loaded right now (with every layer on the GPU), and the GPU's free memory, from one fit plan at the model's full context.
- **A problem is never a check.** A family whose file's last load failed wears the warning triangle in the danger colour and "Last load failed" as its second line, with the reason in the tooltip; a model that cannot run here, or a vision model missing its projector, wears it in the warning colour. A healthy family on this machine shows no glyph (a dot when it is in memory); in Find new models a downloaded family shows the check.

The model library is a two-pane browser: searchable model-family rows on the left, selected model details on the right. Downloaded families and individual variants show checkmarks. Quantizations, conversion publishers, formats and local folder providers for the same identifiable model share a family row, with their separate load, download and setup options under Variants. Different parameter sizes and trained models remain distinguishable. GPU guidance says "Fits on GPU", "Fits on GPU, but limited context size", or "Too big" when evidence supports it, and "Fits on a free GPU" when the model fits the card but not beside what holds it right now (the planner measures free memory, so a busy GPU is never reported as too big); CPU-only and unknown hardware are named honestly, and catalog estimates are not presented as measured context limits. Under the variants, the selected model's GPU facts show what loading it takes (weights and buffers, before context), the KV cost per 1k tokens, the context left on a free GPU (the card less a 2 GB desktop reserve), the context that fits now, and the free memory; when the two context figures differ, one line names the other models in memory and the GB they and other apps hold.

The sidebar plus menu closes after the pointer leaves the button or list, with a 220 ms grace period to cross the gap; re-entering cancels dismissal. The top-level sidebar workspace plus creates a new workspace with a terminal rather than inserting one into the active workspace. Repository-row controls are distinct: their plus creates an agent chat, and their terminal icon creates a shell, both in the clicked repository. The workspace list also shows saved chats whose windows are closed, grouped under their project, so reopening an older conversation does not require remembering its title in another view. Archived chats stay out of this list. Completing a session uses an X control (see *Chat completion X icons*) and moves it to the Completed list, where it stays read-only and restorable for 60 days before deletion. Completing a chat from its card, its saved-chat row or the row menu plays an exit on the row: it folds shut toward its left edge, a little stardust drifts out of where it vanished, then the space closes and the rows below slide up. The chat is saved as completed only after the row has gone; if saving fails the row comes back. The exit takes about 600 ms, the stardust fades within 900 ms, and both are skipped when reduced motion is preferred. The stored archivedAt field remains compatible with existing sessions. Chat headers put folder and branch details directly after the title, followed by a subtle slash divider before actions.

Desktop keeps a Nekko Agent tray icon. Its first action opens a new chat, followed by opening the UI, stopping/starting or restarting the Nekko service, and starting/stopping the model server. Closing the desktop window hides it to the tray while the service and running work remain alive. Explicit Quit shuts down the service and managed processes; the tray's Stop Nekko service stops the service without quitting the UI. Stopping the service is distinct from hiding the window, and restarting restores the UI connection rather than leaving a stale endpoint. Close-to-tray is existing behavior, not newly implemented by the 2026-10-13 notification batch. Keeping the UI hidden does not promise continued execution during OS sleep, shutdown or logout.

**Close guidance and playful farewell (2026-10-15).** `[implemented, focused tests and isolated Electron lifecycle checks; native desktop capture and real Windows notification click verification pending]` The first user close with a running service highlights Nekko's system-tray presence with a Windows balloon and a local companion explaining that agents remain running. The companion is a compact card with no scrollbar: an **X** in its top-right corner, and two slim buttons, **Got it** and **Shut down on close instead** (saves the preference and quits immediately). It dismisses itself after 15 seconds if left alone (2026-10-15; it used to stay until acknowledged and also offered Settings, which lives in the app). **Settings > Desktop behavior** selects keep-running-in-tray (default) or shut-down-on-close; explicit Quit and external installer/migration close requests still quit. **Settings > Fun** groups the existing mascot toggle with a separate default-on **Tray farewell** toggle. Subsequent hides show the smiling, blinking pixel Nekko with a varied goodbye for two seconds, without taking focus; reduced-motion disables blinking. The farewell is a snug rounded card with the cat and text centred, and the window around it is transparent so no dark corners show past the border (2026-11-08). Disabling farewell suppresses that decoration, not the first-close explanation. The companion anchors to the reported tray bounds, clamped to that monitor's work area, falling back to the work-area corner when no tray bounds are available; Windows controls overflow-tray visibility, so exact placement above a hidden icon is not guaranteed. The explanation is deferred while the service is stopped. Notification clicks explicitly restore/focus the main UI, never an auxiliary browser/preview/companion window, and open/focus the corresponding existing agent workspace pane (or open that chat if its pane was closed).
