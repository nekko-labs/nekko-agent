# First-run setup (planned onboarding wizard)

The first launch opens a calm, full-screen setup wizard over the app; every step can be skipped (a per-step **Skip**, plus **Skip setup**), and it never auto-shows again once dismissed (Settings can replay it). It opens with **Welcome** and four questions about the person, then the setup steps:

- **Welcome.** Nekko hops in, waves and says "Hi!" between pixel sparkles: "Hi, I'm Nekko." The drawing is the newest pixel cat (the peeking cat's face, no mouth) in the theme's own surface and ink. Reduced motion shows the last frame. The button reads **Let's go**.
- **What should I call you?** One field. Saved as `userName`; the chat welcome becomes "What should we work on, <name>?" and the Done step says "Nice to meet you, <name>!". Enter moves on.
- **Email (optional).** "We never sell, share or spam": at most one email a month about new features and important fixes, one confirmation email, one-click unsubscribe, and a link to the privacy policy. The per-step skip reads **No thanks** and sends nothing. Next with an address that isn't one stays on the step with "That doesn't look like an email yet." A valid address is saved as `userEmail` and, once per new address, joins Nekko Cloud's `app` list with the name (if given) through the same `POST /v1/signups` the website's beta form uses; it lands in Nekko Cloud's Postgres (Neon) and gets a confirmation email worded for app updates. If Nekko Cloud can't be reached, the address stays saved on the computer and a toast says so. The connection shows as **Update emails** in Settings → Connections.
- **What do you mostly do?** Six cards: Developer, Designer, Writer or researcher, Product or business, Student, Just exploring. Saved as `workProfile`. A card only seeds the next step: Developer starts Detailed with Monitors on, Just exploring starts Minimal, the rest start Regular.
- **How much detail do you like?** Minimal, Regular or Detailed beside a sample chat ("Why is the login test failing?") that replays at the chosen level: Minimal shows only the answer; Regular adds the changed-file count and a collapsed step summary; Detailed adds the reasoning, each tool step and reply stats. The level the work card suggests is marked **Suggested**. A **Show monitors** switch (on for Detailed, off otherwise, until flipped) adds the Monitors panel to the preview. On Next: Detailed turns on Detailed mode; Regular is Simple mode; Minimal is Simple mode with the Changes chip, prompt suggestions and the usage ring hidden (Settings → Simple mode, where they can be shown again); the switch opens or closes the Monitors panel in both modes.

Then:

1. **Look** (was **Theme**). System-match, Light, Dark, and a set of elegant tech presets, each shown as its own small icon drawn in its palette's accent (see below) so the choice is visual, not a word list. Clicking previews live. Setup shows every palette, the seasonal one included, in a single row. A fresh install's setup opens in Dark (a replayed setup, or a theme already chosen, keeps its look). Below the palettes, **Nekko in your chats** switches the per-chat mascot (`mascotEnabled`).
2. **Providers.** Two groups: **online** (ChatGPT leads with one-click *subscription* sign-in so a Plus/Pro plan works without metered API fees; Claude takes an Anthropic API key, with the Claude Agent card joining it in the harness release; plus OpenRouter and a generic OpenAI-compatible endpoint) and **local** (auto-discovery surfaces running Ollama / LM Studio / vLLM servers for one-click add, and an **Nekko Agent** card offers the app's own managed local-model path).
3. **Integrations.** Two groups: **use Nekko inside other tools**, which installs the app as an MCP subagent into detected agent CLIs (Claude Code, Codex, Cursor) with one click, and **connect your apps** (GitHub, Linear, Slack, Discord, Jira, Teams, Gmail, Drive) so workflows and context can reach them.
4. **Work tracking.** Quick toggles for whether agent chats file an issue per change and link the PR to it (both on), and whether the user's prompt, screenshots or other chat context go into issues and PRs (all off until checked). See [issue per change](../code/issue-per-change.md).

## Independent palette and mode (desktop and Local Web UI)

User intent: every offered theme should have light and dark modes, without the mode control replacing the chosen palette. Theme choices should be compact and visual, and Custom colors should no longer fill the page or have a card border.

Acceptance: Nekko, Nebula, Terminal, Nord, Ember, Forest, Blueberry and seasonal Spooky retain their identity in either mode. Selecting a palette keeps the current mode. Switching mode preserves each custom accent independently, while shipped accents adapt for readability. Existing preset IDs and settings remain valid; fresh profiles still follow the computer until a choice is made. No network calls, new permissions or data migration are introduced.

Implemented in Settings → Appearance and the shared onboarding theme step. A 76×36 sun/moon slider switches the selected palette's base mode. All eight offered palettes have light/dark versions; the formerly dark-only palettes inherit the core light surfaces with darker, AA-readable accents. Existing family variants and dark surfaces are retained. The default Nekko palette has its own choice so the mode toggle never has to double as a palette choice.

Each palette is a fun icon instead of a colour circle (Philip, 2026-11-10): Nekko a cat, Nebula a galaxy, Terminal a terminal, Nord a mountain, Ember a flame, Forest an evergreen, Blueberry two blueberries, Spooky the wizard hat and Winter the knitted cat-ear beanie, the two hats Nekko wears in those themes. Gentleface icons where it has one, IconOven's wizard hat, and our own blueberry and beanie, all line icons on the same 16 grid. Each is drawn in its palette's accent for the current mode, line at rest; the picked one turns solid (a 200ms crossfade) with its label in the accent. Hover grows the icon to 108%; pressing shrinks it to 94%. Reduced motion removes the transitions and transforms. Arrow keys/Home/End select within a group; Space activates the mode switch. Custom colors is borderless, capped at 420px and shrinks to fit narrow windows; reset uses the current mode's defaults.

Verification: focused mode/store/markup/contrast tests, desktop typecheck and production renderer builds; real Settings and ThemeStep captured in a hidden, network-blocked Electron sandbox with a disposable profile. Matching default-dark desktop/narrow before/after images, additional light-mode/editor images, real hover/press frames and a short recording are inspected and attached to the UI PR. Renderer interactions cover all eight palettes in both modes, every choice showing its icon with only the picked one solid, custom color retention/reset, keyboard selection and reduced motion. Packaged Windows/Linux, native OS color-picker dialogs, and native iOS/Android pickers are not verified here; the phone theme lists show the same icons (#2525, see [the iPhone spec](../phone/iphone-languages-themes-and-new-chat-choices.md)).

## Answers stay editable

Settings → General → **About you** edits the name and the email (a changed address joins the update list the same way; clearing it removes it from this computer). **Replay setup** reopens the whole wizard. While setup is open, the Agents board's "Agents now live in zones" intro waits until it closes instead of covering it, and the board reloads its Monitors panel choice when setup closes.

Verification (2026-11-07): renderer tests for the answers, the step order and the Minimal choices; nekkod tests for the signup body and route; Nekko Cloud tests for the app-list confirmation email; the real wizard walked step by step in a hidden, network-blocked Electron capture (`onboarding-evidence-sandbox.cjs`), which checked the bad-email stop, the saved answers, the Monitors write and the single theme row. The welcome motion was recorded in headless Chromium. Not verified: a real send to the hosted Nekko Cloud, and Windows/Linux packaged builds.
