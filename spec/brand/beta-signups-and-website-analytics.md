# Beta signups and website analytics (2026-10-17)

**Beta signups.** People will join the beta from a form on nekkoagent.com with their email and, optionally, their name. The form on the home page's beta section posts to the live API (`https://nekko-agent-api.fly.dev/v1/signups`) with the email, `list: "beta"`, the page path, any `utm_*` tags from the URL, a hidden `website` honeypot field, `marketing: true|false` and `policyVersion: "2026-11-03"`. It wakes the API's machine with `/healthz` the first time someone focuses the email field, never on page load. `[changed 2026-11-03]` `[changed 2026-11-08]` The section opens with just **More is coming.** and "Want to get exclusive early features? Join our beta testers list." Signing up is two steps: the email (and the other fields) is saved the moment the button is pressed, then the card asks **What's your name?** with Save and Skip. Save re-sends the same signup with the name, which the API adds to the existing row only if it has none; leaving, skipping or a failed name post loses nothing, and the confirmation email has already gone out without the name. The privacy note mentions the name. It shows a thank-you on success, a try-again-later message on 429 (5 sign-ups per IP per hour), and a retry message on any other failure. The button reads **Get beta invites**. Under the email field, an unticked **Also send me product updates** box is a separate choice: without it the signup is for beta invites only (`marketing: false`), so consent to marketing is never bundled with the beta request. The form says **You must be 16 or older to sign up.** A privacy note under the form says the email is used only for beta invites, and for product updates only if the box is ticked, never shared, and removed on request to hello@nekkoagent.com. `[changed 2026-11-03: GDPR audit GD3; storing the two fields is the API's half, unverified here]` The API accepts browser calls only from nekkoagent.com, so the form can't be tested from a local copy of the site. `[Implemented, unverified until deployed]` Joining twice is harmless and looks the same as joining once, so the form never reveals whether an address is already on the list. We keep only what the form asks for, plus the page path and `utm_*` tags that brought someone there, never a full URL or IP. Sign-ups are double opt-in: a new signup stays pending and gets one "Confirm you want to join the Nekko Agent beta" email from hello@mail.nekkoagent.com (at most one per address per day) whose single-use link, valid 7 days, marks it confirmed and shows a thank-you page; every email has a one-click unsubscribe link. Unsubscribing deletes the sign-up and keeps only a hashed opt-out record so that address is never emailed again; a sign-up not confirmed within 30 days of its confirmation email is deleted (one never emailed is kept). Without the Resend key the signup still saves and no email goes out. `[Implemented, unverified until Resend and DNS are set up]` Each signup moves `pending → confirmed → invited → joined`, or to `unsubscribed`; signing up again after unsubscribing puts the address back to pending. The same table serves later waitlists under another list name.

**Users.** A signup is a request, not an account. Someone let into the beta becomes a **user**, the long-term account record that Cloud accounts will grow from; the signup row links to it. Nothing creates users yet.

**Where it runs.** A small API (`apps/nekko-agent-api`) on one small Fly.io machine, paid from Fly credits, with Postgres on Neon's free plan. Supabase was ruled out on cost, because its two free projects are already in use. Spending stays far under $100 a month. Fly can't cap a bill, so the limit is built into the app's config: one small machine that stops when idle and never scales out, at about $2 a month if it ran nonstop. The signup form wakes the machine when someone first focuses its email field.

**Website analytics.** nekkoagent.com and its docs report to PostHog, in a Nekko Agent project of their own. They track pageviews, clicks and referrers without cookies or any browser storage, so there is no consent banner; there are no session recordings or person profiles. `[Implemented, not live: the PostHog project key and the Neon and Render accounts are owner-side; see TASKS.]`

**Nothing third-party on page load (2026-11-03).** Opening nekkoagent.com, the privacy policy or any docs page contacts only nekkoagent.com, so the site needs no consent banner. The webfonts (Inter Tight, JetBrains Mono, Handjet, Space Mono; OFL-1.1, credited on the credits page) are self-hosted latin subsets in `apps/website/fonts/`, loaded by `fonts.css`, instead of Google Fonts. The download buttons' release info is fetched from GitHub at build time by `scripts/build-docs.mjs` (the build Vercel runs) into a gitignored `release.json`; without it the buttons link to the releases page. The API warm-up waits for the form (above). `[implemented 2026-11-03: GDPR audit GD1, GD2; checked in a headless browser on a local build, not yet on the deployed site]` Known limit: `release.json` is as fresh as the last website deploy, so a release published without a website deploy after it leaves the buttons on the previous build's files until the next one.

**Privacy policy (2026-11-03).** `/privacy` (version date 3 November 2026) covers the beta form and Nekko Cloud accounts. It names every recipient with its region: Vercel (hosting and request logs), Fly.io (the API in `iad`, US, and the Relay in `nrt`, Tokyo), Neon (`aws-us-east-1`), Resend, Supabase Auth, and Apple APNs and Google FCM for phone notifications, and says transfers outside the EU and UK rely on the vendors' Standard Contractual Clauses in their data processing terms. It lists every GDPR right (access, rectification, erasure, restriction, portability, objection, withdrawing consent, complaining to a regulator), sets a minimum age of 16, says product-update emails go only to people who ticked the separate box, keeps confirmed beta signups until the beta ends or the person unsubscribes, keeps the 30-day deletion of unconfirmed signups, describes deleting a Nekko Cloud account (the account, its tokens, machines, synced data and sign-in identity), and says the API keeps no IP address or links with tokens in its logs. The homepage's relay line is qualified the same way: chats and commands are end-to-end encrypted through the relay, but the short Lock Screen status goes through Apple's and Google's push services as plain text. `[implemented 2026-11-03: GDPR audit GD4; the account deletion route and the log redaction it describes are the API's half, landing separately; vendor DPAs are an owner task]`
