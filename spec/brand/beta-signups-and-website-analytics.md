# Beta signups and website analytics (2026-10-17)

**Beta signups.** People will join the beta from a form on nekkoagent.com with their email and, optionally, their name. The form on the home page's beta section posts to the live API (`https://nekko-agent-api.fly.dev/v1/signups`) with the email, `list: "beta"`, the page path, any `utm_*` tags from the URL, and a hidden `website` honeypot field. It wakes the API's machine with `/healthz` when the page loads. It shows a thank-you on success, a try-again-later message on 429 (5 sign-ups per IP per hour), and a retry message on any other failure. A privacy note under the form says the email is used only for beta invites and Nekko Agent updates, never shared, and removed on request to hello@nekkoagent.com. The API accepts browser calls only from nekkoagent.com, so the form can't be tested from a local copy of the site. `[Implemented, unverified until deployed]` Joining twice is harmless and looks the same as joining once, so the form never reveals whether an address is already on the list. We keep only what the form asks for, plus the page path and `utm_*` tags that brought someone there, never a full URL or IP. Sign-ups are double opt-in: a new signup stays pending and gets one "Confirm you want to join the Nekko Agent beta" email from hello@mail.nekkoagent.com (at most one per address per day) whose single-use link, valid 7 days, marks it confirmed and shows a thank-you page; every email has a one-click unsubscribe link. Without the Resend key the signup still saves and no email goes out. `[Implemented, unverified until Resend and DNS are set up]` Each signup moves `pending → confirmed → invited → joined`, or to `unsubscribed`; signing up again after unsubscribing puts the address back to pending. The same table serves later waitlists under another list name.

**Users.** A signup is a request, not an account. Someone let into the beta becomes a **user**, the long-term account record that Cloud accounts will grow from; the signup row links to it. Nothing creates users yet.

**Where it runs.** A small API (`apps/nekko-agent-api`) on one small Fly.io machine, paid from Fly credits, with Postgres on Neon's free plan. Supabase was ruled out on cost, because its two free projects are already in use. Spending stays far under $100 a month. Fly can't cap a bill, so the limit is built into the app's config: one small machine that stops when idle and never scales out, at about $2 a month if it ran nonstop. The signup page wakes the machine when it loads.

**Website analytics.** nekkoagent.com and its docs report to PostHog, in a Nekko Agent project of their own. They track pageviews, clicks and referrers without cookies or any browser storage, so there is no consent banner; there are no session recordings or person profiles. `[Implemented, not live: the PostHog project key and the Neon and Render accounts are owner-side; see TASKS.]`
