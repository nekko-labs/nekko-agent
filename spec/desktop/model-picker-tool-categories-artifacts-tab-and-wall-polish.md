# Model picker, tool categories, Artifacts tab and wall polish (2026-10-15)

User intent (Philip): local models in the picker should read as a name with the file path beneath; provider headings should stand out; the internet switch should turn off internet tools but not local ones, with tools grouped by category; "Focus" should read "Focused"; the wall's three add icons should be in the accent; the agent panel's group **+** must work; and a left-rail **Artifacts** tab should collect what agents produce, grouped by kind, opening the source chat in Focused view.

- **Local model names** `[implemented; TS and Rust golden tests, renderer unit tests]`. The engine daemon's model list (Rust) now carries the engine's friendly `name`, file `path`, folder `location` and load `state` exactly as the TS provider does; before, it dropped them, so under the daemon every engine row showed its full path-like id (`lmstudio/lmstudio-community/...`). The picker shows the short name, the file path as the sub-line, and groups by folder as before. If a local server sends no friendly name and its id is a path, the last segment is the name and the rest becomes the sub-line; cloud ids with a slash (`meta/llama`) are untouched. Filtering also matches the file path.
- **Provider headings** `[implemented]`: in the ink colour at 12px semibold rather than faint 10px capitals; Recent/Starred section labels keep the small faint style so the providers are what you scan for.
- **Tool categories and the internet switch** `[implemented; TS/Rust parity goldens, host routing tests]`. Every tool has a category: **File system**, **Shell & processes**, **Desktop**, **Online** (`fetch_url`, `browser`), **Agent** (plans, questions, sub-agents, watches) and **MCP servers**. Blocking the internet now keeps every local tool and removes Online, MCP and the agent tools that can route to a cloud provider (`spawn_agent`, `delegation_targets`, `agent_watch`, `decide`); before, it removed every tool. The model is only ever offered the remaining tools, and a call to anything else is refused (unchanged gate). The Tools menu is grouped by category with an All on/off per group and stays usable while offline, showing the Online group as off with a note that shell commands are not network-sandboxed. **Boundary:** this is a tool-offer policy plus the existing loopback-only provider check, not an OS network sandbox; a shell command can still reach the network.
- **Focused** `[implemented]`: the wall layout formerly labelled "Focus" reads **Focused** (Ctrl/Cmd+Shift+1 unchanged; the saved mode id stays `focus`).
- **Wall add icons** `[implemented]`: New agent, New image session and New terminal in the toolbar are drawn in the accent colour, with an accent-soft hover.
- **Agent panel group +** `[fixed; isolated renderer reproduction]`. Each project row in the agent panel is a drag source for reordering projects. A press on its **+** (or terminal) button that drifted a few pixels started a project drag, and the click never fired, so the button seemed dead. Pressing either button no longer starts a drag. The existing repository-actions fixture now also sends a real held press that drifts 6px (renderer input events, no OS input): before the fix, 0 creations; after, 1.
- **Artifacts tab** `[implemented; unit-tested; renderer-verified in an isolated fixture]`. A new left-rail destination lists what agents produced across chats: documents a reply linked to (the same links that become artifact cards) and output files the agent wrote with `write_file`, grouped as Documents, Web pages, Designs (pages or images under a design/mockup/prototype folder such as `nekko-designs/`), Diagrams, Data, Office files and Images. Source code and project files (anything under `src/`, `packages/`, `node_modules/` and similar, package manifests, README/SPEC/TASKS/AGENTS) are not listed. Each item names its chat and date; picking one previews it in place with the existing file viewer (HTML stays in its isolated, network-blocked preview), **Open file** hands it to the system, and **Open chat** goes to the Agents wall with that chat as the Focused window (an archived chat opens read-only, as from the agent panel). A filter matches title, filename, chat or path, and archived chats can be included or left out. The index is computed from transcripts in the renderer: no new storage, host calls or permissions; the 60 most recent top-level chats are read, cached transcripts first. A path deleted since is still listed and fails to open. Incognito, image and sub-agent chats are not scanned.

Not verified: packaged desktop app and native OS chrome; the phone apps (no Artifacts tab there); the drifting-press cause was reproduced with renderer input events, not a physical mouse in Philip's running app.

## Model chip name priority (2026-10-16)
Implemented: the closed model picker reserves the selected model name before the secondary provider/account label. `[updated 2026-11-22]` The name stays on one line and ends in an ellipsis when the bar is too narrow; it no longer wraps, which split "Claude Opus 5.5" over two lines in a tiled wall window and pushed the caret out of the bar. The chip also drops the maker and shows the model and version only ("Opus 5.5", not "Claude Opus 5.5"; "GPT-5.1" is unchanged), since the person knows whose model it is. The complete name stays in the chip's tooltip. Verified in a hidden fixture capture at 400px: main wraps, this keeps one line. Caret remains visible; full model/provider information remains in the existing title. Focused render tests and isolated CSS geometry verified; native desktop capture remains unverified.

## Model and effort in one chip, as on the phone (2026-11-22)
**User intent:** "effort shouldn't have a label. it should just be the gauge. Let's combine it with the model selection... similar to the phone version."

Implemented: the composer's model chip reads `[effort gauge] model name ▾`, matching the phone's Model and effort button. There is no separate Effort control or "Effort" word on the bar. The chip opens the model menu, which now has an **Effort** section under the list: one compact row with a slider that steps through provider-advertised levels and shows the current level on the right. No inline level description or token explanation takes space from the model list. Provider default still offers an explicit first choice when needed. If the model has no reported choices, the row shows **Unavailable** instead of a slider. Hover the current value for context about inherited effort or why it is unavailable. The gauge's level is in its tooltip and the chip's accessible name. When Simple mode hides the model but keeps effort, the gauge stands alone on the bar, still without a label. The New agent window's picker keeps its standalone gauge, also without the label. Verified by unit tests and a hidden fixture capture of a wall window in Expert mode (menu open); the Local Web UI shares this renderer and was not captured separately.
