## Guarded chat-switch updates (2026-10-15)

Implemented: picking an existing active chat in the Agents sidebar, or opening one from the toolbar or Add window, is one guarded wall update. When the chat already has a window the tree is kept as is, the chat becomes the active window (the hero in Focus), and picking the chat that is already active changes nothing, so the wall is neither re-rendered nor saved to the host again. A chat with no window still gets one; an archived chat still opens in the read-only reader without joining the wall; a terminal still takes the hero only in Focus; a filter that would hide the opened window is still lifted. When a chat's composer restores its draft, an unchanged attachment list (an empty one included) keeps its existing array, so the attachment strip does not re-render. Per-chat drafts, the 400 ms save debounce and the flush of the last keystroke on leaving a chat are unchanged. No visual change. Verified with focused unit tests and a synthetic off-screen Electron fixture (`apps/desktop/scripts/chat-switch-integration.cjs`; `NEKKO_TEST_REVISION=<rev>` runs a base): reselecting the active chat twice saved the wall once on origin/main and zero times with this change, in Grid and Focus. No latency measurement is claimed; the warm-switch speed work is #438's.

The perf harness's headless browser also refuses to start when its DevTools port is already taken, and accepts only the page opened with its own unique start URL, so a browser left over from an earlier run can no longer be measured in place of the new one or outlive `close()`. `scripts/perf/browser.test.mjs` covers this, including one real launch.
