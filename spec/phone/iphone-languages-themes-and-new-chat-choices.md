# iPhone: the desktop's languages and themes, and New chat's effort and computer (2026-10-23)

**User intent:** Philip asked (2026-10-23) for the phone app to support the desktop's languages, to offer the desktop's themes, with a special limited fall app icon for the Spooky theme, and for a new prompt to choose its model and effort, and the computer it runs on when the model is local.

**Status `[implemented 2026-10-23 on the native iPhone app; unit tests, Linux-safe Swift package tests and two new simulator UI tests (theme picker in English, the app in Japanese) pass on macOS; the New chat effort and Run on rows were built and type-checked but not driven in a UI test (they need a paired computer with a local provider); Android: New chat's effort and Run on implemented 2026-10-27 (T201a); languages and presets implemented 2026-11-02, see [native-android-app.md](native-android-app.md)]`**

- **Languages.** The iPhone app ships the desktop's languages (`LANGUAGES` in `apps/desktop/src/renderer/i18n.ts`): English, Español, Français, Deutsch, Português, 日本語 and 中文 (Simplified). Strings live in an Xcode String Catalog (`apps/ios/App/Localizable.xcstrings`, about 500 strings, plus `InfoPlist.xcstrings` for the permission prompts and the New chat quick action). The app follows the iPhone's language; **Settings → Appearance → Language** shows the current one and opens iOS Settings, where iOS's per-app language picker chooses one for Nekko Agent alone. There is no in-app language list: iOS owns that choice. Not translated yet: the widgets, the Share extension, the Watch app, strings built in NekkoKit (mostly computer and relay error messages) and the chat content itself. Translations were machine-drafted and checked for matching placeholders; a native-speaker review is still owed.
- **Themes.** **Settings → Appearance → Theme** lists *Match my computer* (the default: the computer's preset, light/dark mode and accent, as before, now with the preset's surfaces too), *Match this iPhone*, *Light*, *Dark*, the desktop presets and the experimental families. The catalog is `apps/ios/App/Platform/ThemePresets.swift`, written from `THEME_PRESETS` by `packages/shared/src/themes.ios.golden.test.ts` (CI fails when it is stale; `UPDATE_GOLDEN=1` rewrites it). A preset brings its accent and, in the mode it was drawn for, its paper, surfaces, ink and line colours; System, Light and Dark keep the phone's contrast-tuned palette. An id the phone does not know reads as Match my computer.
- **Spooky's limited icon.** While the theme in use is Spooky (chosen, or matched from the computer), the app switches to the alternate icon `AppIcon-Spooky` (a harvest night with falling leaves, pumpkins and the moon behind the white cat; source `App/Assets.xcassets/AppIcon-Spooky.appiconset/icon.svg`). It is limited to October: from November 1, or on any other theme, the usual icon comes back the next time the app is active. iOS shows its own "You have changed the icon" alert each time, so the app changes it only when it differs.
- **New chat: effort and tools (implemented 2026-10-28, issue #1287).** Effort and Tools show the concrete choice, with no *Default effort*, *Default tools* or *Computer default* option. This iPhone remembers the last chosen effort and tools policy separately for each paired computer, following its existing last-model preference pattern. A fresh choice starts from that computer's effort and tool settings (if received), otherwise the shared Normal/Guardrails fallback. An existing draft keeps its concrete choices; chats started offline carry them too. Picking another computer resolves that computer's own choices, not the previous computer's tools. Forgetting a computer or everything removes these phone-local preferences. They do not change the computer's global settings or sync to another iPhone.
- **Model-specific effort.** The ladder matches the desktop: Claude 4.7 onwards, Fable and Mythos offer Low, Medium, High, Extra high, Max; OpenAI reasoning models offer Low, Medium, Normal, High; others offer Low, Normal, High. A saved rung the model cannot take maps to a supported rung using the shared effective-effort rules (for example Max becomes High on a temperature model, and Normal becomes Medium on Opus 5.5). The concrete supported level is sent through `session:setOptions` and the offline outbox.
- **Recommended is independent.** A recommendation is a general-use marker on a concrete menu option, never an alias for the saved choice or a separate follow-settings option. Effort follows the shared model recommendation (Normal for temperature/OpenAI models, High for native-effort Claude except Opus 5.5 onwards, which uses Medium); Tools recommends Guardrails even when Ask or YOLO is saved. Selecting another option does not move the marker.
- **Peeking mascot laughs on tap (implemented 2026-10-28).** New chat's peeking cat is an accessible button with a local happy-eyes/open-mouth expression and a short bounce. Each tap restarts a 1.2-second laugh, then returns to idle. Reduce Motion preserves the expression and accessible Laughing feedback without the bounce. Backgrounding pauses motion and leaving cancels the timer. It sends no message, changes no settings, plays no sound and uses no network.
- **New chat: Run on.** When the chosen model's provider is local (`LOCAL_PROVIDER_KINDS`: llama.cpp, Ollama, LM Studio, vLLM), a **Computer → Run on** row lists the paired computers. Choosing another connects to it (one connection at a time, as before), clears the model, folder and explicit effort/tools overrides since those belong to the computer, keeps the typed text, and picks that computer's last or default model and last-used effort/tools. The row stays while that computer's models load.
- **Phone access (decided in this change).** `effort` joins the chat options a phone may set (`PHONE_SESSION_OPTION_KEYS`); its value must be one of `low`, `medium`, `normal`, `high`, `xhigh`, `max` (`PHONE_EFFORT_LEVELS`, written to `phone-access.json` as `effortLevels` and enforced by the Rust gate), else `value-invalid`. Effort changes only how hard the model works, so it needs no proof, unlike raising the chat mode.
- **Not yet:** a UI test of the New chat rows against a live computer, native-speaker review, and translating the extensions.

## Issue #1287 verification

Focused protocol checks cover computer effort parsing, supported-rung normalization and independent recommendations. App preference tests cover persistence, per-computer isolation, corrupt values and computer-setting fallbacks. A Debug-only New chat fixture uses the real screen with an offline draft, no paired computer and no network startup. Simulator UI tests cover concrete menus, independent recommendation markers, repeated taps, return to idle and the reduced-motion branch (a Debug-only launch override; a physical iOS Reduce Motion toggle is not claimed). Baseline/after screenshots and a short motion recording belong in PR evidence, not git. A live paired-computer round trip and physical-device/VoiceOver inspection remain separate from fixture coverage; no new claim of those checks is made here.

The shared read-only `PHONE_SETTINGS_VIEW` now includes `effort`; the regenerated daemon contract and TypeScript/Rust gate tests cover its projection. It remains excluded from phone-writable global settings. Before settings arrive, first use falls back to model-normalized Normal; phone-saved choices take precedence.
